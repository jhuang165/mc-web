# Original item and Creative subtype parity catalogue

Generated by `node tools/build-content-catalogue.mjs`. Refresh native evidence with `node tools/verify-catalogue.mjs` (local original JAR/JDK required). [Roadmap](parity-roadmap.md) · [native evidence](content-registry-reference.json).

Includes **315 original item registrations** and **606 Creative search entries**, including **76 additional enchanted-book NBT entries**. Every registration appears, including technical items with no Creative listing. A row with no metadata is an unlisted registration, not an invented obtainable subtype. Registry properties (Creative tab, stack limit, hasSubtypes, maximum durability) are retained in the JSON evidence.

Browser IDs are `internal ID:stack damage`. The **167 listed browser entries** are matched to exact Creative subtypes using the existing inventory/Creative mappings. Listed means Partial; it does not verify use, acquisition or persistence. Unmapped means the current evidence has no mapping, and requires review before declaring Missing. NBT entries have no browser mapping. Creative is not an exhaustive catalogue of arbitrary NBT combinations, all potion values, durability states, firework configurations, map contents, or player-authored data. Those require separate semantic cases. No row is certified fully verified.

## Acceptance and dependencies

Each row inherits the gates in its last column. Evidence here verifies native registration/subtype enumeration only; browser behavior remains an audit. Dependencies refer to [roadmap](parity-roadmap.md) work packages/milestones.

| Gate | Dependencies | Required acceptance before behavior verification |

| B | WORLD-01, ordinary content | I plus block placement/orientation, item-damage to world-metadata conversion, bounds/rays/collision/support, neighbor/scheduled/random updates, light/render/sound, harvesting/drops and round-trip persistence; use the separate metadata audit |
