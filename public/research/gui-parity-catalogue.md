# Original screen and GUI support parity catalogue

Generated by `node tools/build-surface-catalogue.mjs`; refresh original evidence with `node tools/verify-surface-catalogue.mjs` (JDK, pinned client JAR, MCP SRG names and local libraries). [Roadmap](parity-roadmap.md) · [original evidence and provenance](surface-registry-reference.json). Enumeration does not certify whole-feature parity.

Status counts (batch 19 audit, 124 rows): 99 Partial, 25 Out of scope. (screens plus support classes; batch 19 audit re-checked every Missing and Partial row against src/menus.js, menu-screens.js and the research docs.)

The original JAR contains **58 classes in the GuiScreen inheritance tree**, including the base, container/effect bases and screens outside the gui package. A separate **66 mapped classes/interfaces in the client/gui namespace** covers HUD, fonts, widgets, lists, entries, callbacks and other helpers that are not screen descendants. These are exhaustive within those explicit class-selection rules, not a claim that there are 124 independent screens. Anonymous/inner helpers remain distinct. Class header parsing records inheritance/abstract flags without initializing GUI classes or requiring GL. No layout, navigation or rendering is executed by this extractor.

The Partial rows are reviewed conceptual browser counterparts, with current evidence/limits linked. Multiple original screens may share one adapted browser modal. Missing means no browser counterpart was found in src/ (batch 19 audit); Out of scope marks multiplayer, Realms, Twitch, demo, snooper and JVM-only screens. Realms/Twitch and other original external-service screens are retained in the inventory; service availability and browser-specific constraints need explicit acceptance decisions. Supporting classes outside client/gui, overlays outside GuiScreen, all settings/control values and GUI substates need separate semantic audits.

| Gate | Dependencies | Full acceptance required |

| I | Inventory/content/NBT/authoritative transactions | U plus exact slot coordinates/stack rules, carried cursor, click/drag/shift/hotbar/drop/double-click, special outputs and costs, container ownership/distance/closing/drops, server synchronization and reload scenarios |
