# Original entity registry parity catalogue

Generated by `node tools/build-content-catalogue.mjs`; refresh native evidence with `node tools/verify-catalogue.mjs`. [Roadmap](parity-roadmap.md) · [original-class enumeration evidence](content-registry-reference.json). No row is certified whole-feature verified.

All **57 numeric EntityList registrations**, read from its complete map rather than inferred from spawn eggs. Native class names are obfuscated names from the pinned original JAR. Abstract entries are registrations, not independently spawnable creatures. Spawn-egg presence is native evidence only; the browser has spawn eggs for 24 mobs; every concrete registration is a `/summon` type (55 of 55, 2 abstract) ([spawn eggs](spawn-eggs.md)).

Status counts (batch 19 audit, 57 rows): 20 Implemented, 35 Partial, 2 Abstract registration.

Status words (batch 19 audit; the rows with `/summon`, server or region-import notes were re-read in the batch 67 audit against src/, src/multiplayer and the batch 59-66 notes; every Partial row was re-read in the batch 82 audit, 2026-11-18, and now says what keeps it Partial): **Implemented** means the browser has the entity and the linked doc replays it against native probe records; it is never whole-feature verified, because natural spawning is a SpawnerAnimals port with the approximations in [natural spawning](natural-spawning.md) and each doc lists approximations. **Partial** names the specific gap. **Missing** was confirmed absent in src/; no row is Missing (the Abstract and spawn-egg columns' "no" is native evidence, not a status). Per-mob gaps beyond the row text are in [remaining gaps](remaining-gaps.md).

Gate **E** depends on WORLD-01/SIM-01 plus player/combat, mob/spawning, transport, progression or dimensions as applicable. Each row requires native identity and variant metadata, dimensions, attributes, spawn/despawn/caps, movement/collision/fluids, AI/targets/interaction/equipment, damage/immunity/knockback/attribution, drops/rewards, render/animation/sound, save/unload/reload and cross-system acceptance cases. Partial links state current evidence and limitations; registry extraction verifies enumeration only.

EntityList is not the complete feature roster: players, weather lightning, thrown eggs and fishing hooks need separate non-registration cases; rider/jockey combinations, baby/tamed/equipment/difficulty states, wither skeletons, zombie villagers, charged creepers, horse variants, bosses and multipart entities require semantic subcases. Registration coverage does not close that work.
