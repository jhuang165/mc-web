# Live ender pearl use and flight

This tranche connects internal item 378 (vanilla item 368) to the existing throwable system. `Projectiles.throwEnderPearl` uses the same `EntityThrowable` launch, ray trace, entity sweep, drag, gravity, water and tick behavior already used by snowballs and eggs. The renderer maps `kind: "enderPearl"` to item sprite 378. `throwHeldItem` now accepts the item and keeps the existing Snowball/Egg behavior intact.

The pinned-JAR `ItemEnderPearl` probe executes its original right-click method against a recording world. Survival decrements the stack first and plays `random.bow` at volume 0.5 with the native random pitch; only the server spawns the pearl. Creative returns before decrement, sound, or spawn. The same probe inspects the declared `EntityEnderPearl` methods and confirms it adds only `onImpact`; flight is inherited from `EntityThrowable`. See [the use reference](ender-pearl-use-reference.json).

At collision, `Projectiles.tick(world, targets, onHit, onPearlImpact)` requires the synchronous fourth hook for pearl kinds. It passes `{ pearl, world, hit, target, block }`. The hook can call `impactEnderPearl` and supply `hit`, `particle`, `dismount`, `teleport` and `damage` adapters. The hit adapter runs first for zero thrown damage, followed by 32 portal particle hooks using the pearl's same `random`/`rand` object, then owner dismount/teleport/fall reset/fall damage. The module leaves client pearls alive for server synchronization and sets server pearls dead even when their owner fails the teleport gates. It throws if a pearl collision has no hook, so impact cannot be silently treated as a snowball hit.

Projectiles serialize pearl `kind` and local owner token `owner: "player"`. Loading rejects pearl rows with a missing or unknown owner token and rejects unknown projectile kinds; old records with no kind still load as snowballs. The local token survives JSON save/reload and is resolved by the live player adapter at impact rather than retaining an object reference. Reload creates a new entity RNG stream, matching the existing browser projectile model; exact entity RNG continuation is not saved. Native `EntityThrowable` NBT includes ownerName and in-ground/shake fields, so complete Java entity-NBT parity is not claimed.

Focused coverage runs actual Projectiles block and entity impacts through the hook, verifies hit/particle/teleport/damage order, Creative/Survival item-use outcomes, owner/kind reload, render icon mapping, and existing snowball/egg tests. The parent has wired `main.js` through a local-player impact adapter and actual portal FX, with a block-impact/live-damage integration test. The connected native `EntityPlayerMP` teleport branch remains bytecode-derived and adapter-tested; this work does not claim execution against a live native server connection.
