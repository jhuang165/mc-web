# Original command parity catalogue

Generated by `node tools/build-surface-catalogue.mjs`; refresh original evidence with `node tools/verify-surface-catalogue.mjs` (JDK, pinned client JAR, MCP SRG names and local libraries). [Roadmap](parity-roadmap.md) · [original evidence and provenance](surface-registry-reference.json). Enumeration does not certify whole-feature parity.

All **48 command registrations** in the original ServerCommandManager constructor: common entries plus dedicated-only entries and integrated-only publish. Registration membership/order comes from inspected constructor bytecode. The unchanged individual constructors, name/alias/default-permission/usage getters and CommandHandler.registerCommand execute in the probe. The actual ServerCommandManager constructor and command bodies are not executed; no server starts. Profile alias maps reproduce native registration with **35 integrated** and **50 dedicated** lookup keys, not 85 distinct commands.

The declared permission number does not prove access: commands marked custom check override the base sender permission logic. Operator level, integrated-server rules, server configuration, sender kind and command-specific conditions need behavioral cases. Usage values are original translation keys, not a full syntax/subcommand inventory. Browser controls that change time, mode or seed are not slash-command implementation. No generalized browser command system exists.

Gate **Q** depends on SIM-01, authoritative world/player state, chat/console/command blocks, permissions, selectors, NBT and affected gameplay systems. Each registration needs all syntax/subcommands, aliases, parsing/relative coordinates/numeric bounds, selector expansion, permissions/sender restrictions, exact mutations and tick order, error/feedback translations, tab completion, command-block output, statistics/scoreboards, save/reload and multiplayer synchronization. Command/subcommand semantics remain open; a command name is not an exhaustive feature case.
