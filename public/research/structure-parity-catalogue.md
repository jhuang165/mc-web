# Original structures and feature-generator parity catalogue

Generated by `node tools/build-surface-catalogue.mjs`; refresh original evidence with `node tools/verify-surface-catalogue.mjs` (JDK, pinned client JAR, MCP SRG names and local libraries). [Roadmap](parity-roadmap.md) · [original evidence and provenance](surface-registry-reference.json). Enumeration does not certify whole-feature parity.

The unchanged MapGenStructureIO static registration produces **5 structure start IDs** and **48 piece IDs**, with forward/reverse maps checked by the probe. These are native save/dispatch IDs, not an inventory of every procedural configuration. All are listed below. Separate class-header inventories list **10 top-level MapGen drivers/framework classes** (structure IO/data helpers excluded) and **41 mapped WorldGen feature classes**, including abstract bases.

Dungeons, desert wells, End spikes, bonus chests, trees and decorators are feature generators, not additional MapGenStructureIO starts. Temple pieces distinguish desert/jungle pyramids and swamp huts; a shared start ID does not merge those features. New Java worlds (generation 9 and later) use the ported Java caves, ravines, ores and decorators; only the legacy custom landscapes (versions 1-8) differ. Status words: Implemented means a port replayed against native records and live in new worlds (doc linked), Partial names the gap, Missing was confirmed absent. A ported feature does not prove native seed/call order, biome selection, distribution, population or complete configuration support. No world generation is executed by this extraction.

| G | WORLD-01/WORLD-02, native RNG/terrain/decorators and relevant content | Every generator configuration/variant, place/support/light/height/boundary rules, block/metadata output and return value, exact random calls, biome/dimension scheduling/distribution and cross-chunk population under fixed seeds and different exploration/reload orders |
