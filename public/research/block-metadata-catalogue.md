# Original block metadata audit

Generated by `node tools/build-content-catalogue.mjs` from [original-class registry/subtype evidence](content-registry-reference.json). [Base blocks](block-parity-catalogue.md) · [item subtypes and acceptance gates](item-parity-catalogue.md) · [roadmap](parity-roadmap.md).

All **171 block registrations** need classification of their 16 possible raw 4-bit values (**2736 raw ID/metadata combinations**). This is the storage audit domain, not a claim of 2736 meaningful or valid variants. Every value remains Unclassified until native placement, update and read behavior identifies its semantics, ignored/aliased bits, unreachable values and invalid-state handling. Do not count this scaffold as completed semantic metadata coverage.

The Creative column lists actual `item ID:damage` returned by native Block.getSubBlocks for blocks with a Creative tab and item representation. Empty means no enumeration under those conditions. It does not imply that the block cannot be obtained, has no drop, or has no world variants. Item registration identity alone does not establish block-placement behavior. Item damage is **not** world metadata: log axis, leaf flags, slab halves, sapling stage, fluid levels, orientation and powered states need explicit conversion cases.

Every row requires gate **B** in the [item catalogue](item-parity-catalogue.md): dependency WORLD-01/content plus original evidence for placement, metadata meanings/bit fields, bounds/rays/collision, support/neighbor/tick behavior, light/rendering, harvest/drops, sound and persistence. Each raw value must become a named semantic case, an alias/ignored-bit case, or a documented invalid/unreachable case before this audit closes. Existing probes cover subsets; this table does not promote them into whole-block verification.
