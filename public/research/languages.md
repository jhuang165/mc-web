# Languages and the unicode font

Target: Minecraft Java 1.7.10 (client sha1 e80d9b3b...). Not full parity; see the gaps below.

## Evidence

`tools/probes/LanguageProbe.java` runs the **unchanged** `bbu` (FontRenderer) and `brs` (Locale) classes from the jar through test doubles for `Minecraft`, `GameSettings`, `TextureManager` and `IResourceManager`. `tools/verify-languages.mjs` (needs `MC_RESEARCH`) asserts that `src/font-renderer.js` and `src/lang.js` agree with them and writes `public/research/languages-reference.json`:

- character widths for all 65536 characters with the unicode flag off and on;
- string widths for strings with unicode text, bold and section codes;
- the Locale parser, fallback order and unicode threshold on fixtures, and the unicode flag and key count of each of the 73 real language files.

`src/languages.test.js` replays the recorded rows. The structure of `GuiLanguage` (list sorted by code, "name (region)", Force Unicode Font button, no bidi button in 1.7.10) and `GameSettings` (`lang:`, `forceUnicodeFont:`) was read from bytecode, not probed.

## Rules

- Locale loads `["en_US", selected]`; later keys win, so a missing translation is English. Lines: skip empty and `#`, split at the first `=`, rewrite `%n$d` / `%f` style arguments to `%s`.
- Unicode flag: `Locale.isUnicode() || forceUnicodeFont`. `isUnicode` is more than 10% of the merged values' characters at or above 256, compared as floats (exactly 10% counts). The brief's "1%" is not what the bytecode does.
- Widths: ascii.png cells give `(int)(0.5 + (rightmost opaque column + 1) * 8 / cellWidth) + 1`; with the unicode flag, or for characters outside the 256 table, `glyph_sizes.bin` (signed byte; start = byte >>> 4, end = byte & 15, end > 7 reads as 0..15) gives `(end + 1 - start) / 2 + 1`. Space is 4, `§` is -1, bold adds 1 per visible glyph.

## In the game

- `npm run lang:fetch` (`tools/fetch-lang.mjs`) installs the 73 `.lang` files from the asset index into the ignored `public/lang/1.7.10/` with SHA-1 checks and writes `manifest.json`, following `tools/fetch-music-streams.mjs`. Without the manifest only English (US) is offered and the Language screen says so. The language files are Mojang's and are not committed.
- The Language screen (`src/menus.js`) lists languages sorted by code, marks the current one, and has Force Unicode Font. Choices persist in `options.txt` (`lang:`, `forceUnicodeFont:`).
- Selecting overlays the language onto the menu strings, command texts (chat translations), achievements and death messages at once (`src/lang-hooks.js`); keys missing in the file stay English.
- `public/media/1.7.10/font/glyph_sizes.bin` ships with provenance. The unicode glyph pages (`unicode_page_XX.png`, already shipped in `public/media/1.7.10/font/` with provenance entries) are drawn at half scale by `src/menu-ui.js` for menus, chat and books widths.
- Localization round 2 (batch 16): `stackName`/`displayName` (`src/item-names.js`) is the one display-name function: a custom (anvil/NBT) name first, then the selected language through the unlocalized item keys, then the baked English name. Used by the item tooltip, the held-item name popup, command output and the anvil. The keys (`src/item-keys-data.js`, 315 items, per damage) are probed: `tools/probes/ItemKeyProbe.java` runs `Item.getUnlocalizedNameInefficiently(ItemStack)` of the unchanged jar for every registered item/block-item and damage 0-15 (0-255 for the spawn egg), recorded in `public/research/item-keys-reference.json` by `tools/verify-item-keys.mjs`; the script also asserts that the jar's en_US value of each key equals the already-probed English display name (zero mismatches). Names the item class composes (potion 373, spawn egg 383) are not plain `key.name` lookups: potions use `item.emptyPotion`, `potion.prefix.*`, `<effect>.postfix` and `item.potion.name`; spawn eggs use `item.monsterPlacer.name` + `entity.<EntityList name>.name` (the entity names per damage are probed too). Those two compositions are bytecode-read (the English results are replayed against `item-names-reference.json`).
- Container titles and labels (`src/container-names.js`): Inventory, Crafting, Furnace, Repair & Name, Enchant, Chest, Large Chest, Ender Chest, Dispenser, Dropper, Item Hopper, Brewing Stand, Minecart, Villager (`entity.Villager.name`) and Beacon (`tile.beacon.name`) map from their default English title to the lang key (keys bytecode-read; the en_US values are checked equal to the English titles). A custom container name is left alone, except that one identical to a default English title is localized as well. Also through the language: potion tooltip lines (effect names, potency, `potion.empty`, `potion.effects.whenDrank`, attribute names), enchantment names, `item.unbreakable`, the attack damage line, bed messages and Leave Bed, and the Now playing line.
- Translations round 3 (batch 17, `src/lang-keys.test.js`, `public/research/lang-keys-reference.json`, `tools/verify-lang-keys.mjs`): `tools/probes/KeyTraceProbe.java` swaps the unchanged jar's `StatCollector` translator (`dd.a`) for one that answers `<key>` for every key, so what the original classes build shows its keys and formatting. **Probed**: the 12 creative tab labels and keys (`CreativeTabs.creativeTabArray`, `getTranslatedTabLabel` = `itemGroup.<label>`), and the `ItemFirework`/`ItemFireworkCharge.addInformation` lines of 28 fixtures (`item.fireworks.flight` + " " + flight; per explosion `item.fireworksCharge.type.0-4` or `.type` for an unknown shape, dye colours `item.fireworksCharge.<black|red|...|silver|...|white>` or `.customColor`, `.fadeTo`, `.trail`, `.flicker`; lines after the shape are indented two spaces inside a rocket). Routed through `translate`: `src/fireworks.js` (all tooltip lines), `CREATIVE_TABS[i].name` (a getter, so the tab title, hover label, aria-label and the search tab's per-item tab line follow the language), `horseChestTitle` (`entity.horse|donkey|mule|zombiehorse|skeletonhorse.name`, translated when the container is built as `EntityHorse.func_110226_cD` does; a custom name stays), the horse and trade GUIs' "Inventory" label (`container.inventory`), the beacon GUI (`tile.beacon.primary`/`secondary`, button tooltips `gui.done`/`gui.cancel`, and each power's potion name key plus the literal ` II` of the secondary tier) and the Ender Dragon / Wither boss bar names (`entity.EnderDragon.name`, `entity.WitherBoss.name`). **Bytecode-read** (javap on `bez`, `bfa`, `bfb`, `bfc`, `bfv`, `wi.b_`, `sa.b_`, listed in the reference's `bytecode` object; the script asserts each key exists in en_US): the beacon, trade and horse GUI keys and the boss bar names. English (US) output is unchanged; the GUIs have no other text labels in 1.7.10 (the horse and trade screens draw only the title and `container.inventory`).
- A resource pack's `ascii.png` is measured with the same width computation; its `font/glyph_sizes.bin` replaces the shipped one.

## Gaps

- Batch 18: in-game text now goes through the same glyph renderer as menus and chat (`src/bitmap-text.js` over `menu-ui.js` `textHtml`, cached per font state): item tooltips (the box follows `GuiScreen.drawHoverText`: width = widest `getStringWidth`, 3 px padding, 4 px after the title and 2 px between lines, § colours), stack counts (`RenderItem.renderItemOverlayIntoGUI`: right edge at x + 17, top at y + 9, white with the native shadow, yellow for the creative 0/full marker the port draws), container titles and the "Inventory" label (0x404040, no shadow), the held-item name, the "Now playing" line, the boss bar title, the F3 overlay and the XP level (four black copies at +/-1 px and one 0x80FF20 copy, as `GuiIngame` draws it). The positions and colours were read from the unchanged 1.7.10 bytecode with `javap` (bny, bdw, bbv); they were not probed at runtime. Not verified in a browser. Signs are still drawn on a canvas with the TTF (ASCII only; a unicode sign line is not drawn with unicode pages), the DOM-only menu text the port invented (pause menu notes, command-block dialog) is unchanged, and the F3 text colour (0xE0E0E0) is the menus' grey, not re-read from the debug-overlay class.
- Still English: `Durability:` (hard-coded in 1.7.10 too), `item.skull.player` heads, achievement/statistics screens beyond b15 and the accessibility-only `aria-label`s the port invented (Next trade / Previous trade). Entity names in the F3 overlay go through `entity.<EntityList>.name` (`src/entity-names.js`, a name tag's `customName` first, as `getCommandSenderName`). A Wither/Dragon boss bar shows the entity's `customName` when one is set (the summon/NBT path for these two bosses does not set it yet). Death messages are built by the ported combat tracker (`src/combat-tracker.js`, [combat.md](combat.md#combat-tracker-and-death-messages)) and formatted through `translate` for every `death.attack.*` and `death.fell.*` key (`.player` and `.item` variants included; the item prints as `[Name]`); `lang-hooks.js` overlays both tables. Internal-only items with no 1.7.10 key keep their Title Case English name. Signs hold player text and are not translated in 1.7.10 either.
- Batch 27 modal2 (probed against the unchanged jar, `tools/probes/FontStyleProbe.java`, `tools/verify-font-style.mjs`, `public/research/font-style-reference.json`, `src/font-style.test.js`):
  - **Styles on every glyph page.** `renderStringAtPos`/`renderUnicodeChar`/`doDraw` replayed over 35 strings for both unicode flags, shadow and plain (140 rows, `§k` excluded): glyph quads and the underline/strikethrough bars match vertex for vertex in float32 (`src/font-quads.js`). Facts: the pen moves by `(int) advance` (half advances never accumulate); the shadow pass is drawn at +1 +1 with an extra -f offset (f = 0.5 unicode, 1 ascii) for glyphs not drawn from `ascii.png`; the style flags are not reset between the shadow pass and the normal pass; bold draws the glyph again f to the right and widens the advance by 1; italic moves the top corners +1 and the bottom -1; strikethrough bar y + 3 .. 4 and underline bar y + 8 .. 9 (starting 1 px left) use the float advance. The DOM text (`menu-ui.js` `textHtml`) now draws the bars as 1 unit elements and italic as `skewX(-14.04deg)` (a 2 in 8 lean) on ascii and unicode glyphs alike instead of CSS `text-decoration`/`font-style`; sign text (`sign-font.js`) already drew bars and leaned glyphs on a canvas and now advances the pen by `(int)` as well, which also corrects unicode sign lines whose half advances used to accumulate. Unicode glyph spans (`glyphHtml`) have the integer width. Not pixel-compared in a browser against a native screenshot.
  - **Bidirectional languages (ar_SA, he_IL).** `FontRenderer.bidiReorder` is `new Bidi(new ArabicShaping(LETTERS_SHAPE).shape(s), DEFAULT_RTL)` then `writeReordered(DO_MIRRORING)` (ICU4J 51.2); `drawString` applies it to the whole string, colour codes included, and `drawSplitString` right aligns each line on the reordered width. Ported in `src/bidi.js` (Unicode 6.2 bidi algorithm as ICU 51 runs it: no isolates, no bracket pairs; Arabic shaping with the lam-alef ligatures and transparent tashkeel) with tables generated from the client's ICU data (`tools/gen-bidi-data.mjs` -> `src/bidi-data.js`). `src/lang.js` sets `font.bidi` with the language (`setBidiFlag`), `textHtml`, `Gui.splitText` and sign layout apply it. Checked against the unchanged class over ~15,000 random strings (Latin, Arabic incl. presentation forms and whole blocks, Hebrew, digits, marks, explicit embeddings, punctuation) with no difference; 418 are recorded in the reference and replayed in `src/font-style.test.js`.
  - Known difference: text of several paragraphs (a literal CR, LF, NEL, U+2029 or U+001C inside one string) where a later paragraph has no strong character. ICU 51 gives such a paragraph a level this port does not reproduce in all cases (for example `a\n\n(` stays left to right natively but `a\n(` mirrors the bracket); about 1 in 1000 random strings that contain separators differ. No game string contains a separator; chat and signs split lines before drawing.
- Random (`§k`) text picks glyphs of the same width on both pages, it is not replayed against the native random stream.
- Characters whose `glyph_sizes.bin` byte is 0 draw nothing, as in the original.
