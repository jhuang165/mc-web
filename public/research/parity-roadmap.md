# Vanilla Java 1.7.10 parity roadmap

Owner accepted 2026-11-01. The complete roadmap and rationale are durable shared memory in `.shared-memory/notes/parity_roadmap.md`. This is the execution tracker; [coverage](parity.md) describes current behavior. Full parity remains unfinished. Forge/mod compatibility is outside this vanilla roadmap. Do not infer completion percentages from test counts or registry mappings.

Status: **Missing** = no implementation; **Partial** = some behavior exists; **Implemented** = acceptance behavior works; **Verified** = named evidence passes, limited to its stated scope. Original-class execution, bytecode inspection, browser observation and port-only regression tests are distinct evidence. A work package is complete only when all its criteria pass.

Finish PLAN-03 while closing confirmed existing-system persistence defects, then FX-01/PLAYER-01 and WORLD-01/SIM-01. Build new block families and containers on those foundations; advance redstone, progression, mobs and generation before dimensions and interoperability. User-reported correctness takes precedence. Continue localhost development; do not publish the Site without owner instruction.

## Current evidence limits

The scheduled-tick persistence tests are port regression tests, not execution of original Anvil/TileTicks serialization. Existing native water/lava/fire behavior probes remain unchanged. Since 0.22.4 fire scheduling tests restore the weather World.rand/updateLCG snapshot rather than manually assigning a seed. `src/random-persistence.test.js` verifies scoped weather timer/block-selection continuity and JavaRandom state/cache validation. This is a browser save extension, not execution of Java Random or updateLCG serialization in world NBT. Since 0.22.5 the fluid and tree runtimes share that restored World.rand with weather/fire. A 160-step controlled interleaved regression covers lava slowdown, sapling growth, leaf decay/drops, fire queues and repeated JSON/import reloads; this is port regression evidence, not execution of native cross-system tick ordering. Original WorldServer random/scheduled block-update call sites were inspected in bytecode to confirm they pass the World.rand field. Authoritative explosion draws join the saved stream in 0.22.6. Entity/other streams, active lightning state, weather-strength reset and complete whole-world continuity remain SAVE-03. Since 0.22.3, falling sand/gravel use the same versioned pending-tick representation alongside their existing entity array; repeated mid-column reload tests and import payload checks cover schedule continuity, without executing original TileTicks serialization. Relative delays and ordering are preserved within each scheduler; cross-system WorldServer priority/order is not yet unified. Old exports without tick snapshots use the existing wake migration. Invalid snapshot envelopes fall back to migration; invalid individual entries are skipped.

## Catalogue evidence and regeneration

`node tools/verify-catalogue.mjs` executes unchanged original registration/subtype classes from the SHA-1-pinned 1.7.10 client JAR. It enumerates all items and blocks, reproduces all 606 entries of the independently captured Creative search list, retains 76 enchanted-book NBT entries, reads EntityList's full ID map, scans occupied biome slots and records GameRules constructor defaults. Native registration/subtype execution verifies enumeration only. It does not execute feature behavior or establish browser equivalence.

`node tools/build-content-catalogue.mjs` regenerates the five linked audit catalogues without a JDK. It validates native identities, subtype uniqueness including NBT, independent Creative-reference equality and exact coverage of all 167 current browser search entries. Unmapped rows require review; mapped listings remain Partial. Metadata item damage and world block metadata are different domains. Biome registry slot 161 has native declared biomeID 160; both identities are retained. Registered abstract entity bases are marked, and nonregistered entities/semantic variants remain separate open work. Catalogue changes do not change the app runtime/version or publish the Site.

`node tools/verify-recipe-catalogue.mjs` extracts the original sorted CraftingManager list, full FurnaceRecipes input/result map and its separate output/XP map. It executes fixed-recipe matching at fitting offsets/mirrors with single-count stacks and wildcard damage sampled as zero; shapeless grids use compact layouts. `node tools/build-recipe-catalogue.mjs` generates the recipe audit and replays mapped results/float32 XP. Exact native classes distinguish five special handlers (including map-extension's shaped subclass) from fixed recipes. Native fields, null/count-zero dynamic outputs, wildcard metadata, empty cells, copy-NBT flags and duplicate native XP-map entries are retained. Repair is a separate manager branch, not a registered recipe. This is registration plus limited matching evidence; dynamic semantics, rejection cases, all wildcard values, shapeless permutations, fuel/payout/container and acquisition acceptance remain open. The audit discovered and closed RECIPE-01 without adding new item types.

`node tools/verify-surface-catalogue.mjs` reads the SHA-1-pinned original JAR and local MCP SRG names (mapping SHA-256 retained). Command membership/order is inspected from ServerCommandManager constructor bytecode; unchanged command constructors/metadata getters and CommandHandler registration execute for both reconstructed profiles. The ServerCommandManager constructor, command execution and permission outcomes are not run. Unchanged structure static registration runs with forward/reverse-map checks. Screen inheritance, GUI supporting classes, MapGen and WorldGen feature inventories are parsed from original class headers without GUI initialization, GL or generation. `node tools/build-surface-catalogue.mjs` creates the three linked audit tables with explicit selection scopes, conservative browser statuses and acceptance/dependency gates. Abstract/framework/inner classes are retained without counting them as independent features. Default permission levels are not access verification; command overrides are marked. Per-subcommand, GUI-state, generator-configuration and remaining metadata/NBT feature cases remain open. This catalogue tranche changes no app runtime/version.
