# Resource Packs (GuiScreenResourcePacks, ResourcePackRepository)

Target: Minecraft Java 1.7.10. Not full parity; see "Remaining differences".

## Evidence

Bytecode-read with `javap -c` on the pinned client jar (sha1 e80d9b3b...), **not probed** (GUI classes need GL and a running Minecraft): `bgf` (GuiScreenResourcePacks), `bgk`/`bgj`/`bgl` (GuiResourcePackList, Available, Selected), `bgg`/`bgi`/`bgh` (list entries and the Default entry), `brc`/`brf` (ResourcePackRepository and its Entry). Numbers taken from them:

- Buttons 150 x 20: "Open resource pack folder" at `width/2 - 154`, Done at `width/2 + 4`, both at `height - 48`. Title `resourcePack.title` at (`width/2`, 16) white; `resourcePack.folderInfo` at (`width/2 - 77`, `height - 26`), color 0x808080.
- Lists 200 wide: Available at `width/2 - 4 - 200`, Selected at `width/2 + 4`; slot top 32, bottom `height - 55 + 4`, row height 36, a 13 unit header holding the underlined bold list title; scroll bar at the list's right edge - 6.
- Row: 32 x 32 icon, name at (`x + 34`, `y + 1`) white (cut to 157 with "..."), description wrapped at 157, two lines at `y + 12` and `y + 22`, color 0x808080. While hovered, the icon gets a 0xA0909090 overlay and the arrow cells of `textures/gui/resource_packs.png` (256 x 256): right arrow (0, 0/32), left arrow (32, 0/32), up (96, 0/32), down (64, 0/32); the second v is the hovered variant.
- Click rules (`bgg.a`): with the pointer inside the 32 px icon, an available entry moves to index 0 of the Selected list; on a selected entry x < 16 moves it to index 0 of Available, x > 16 and y < 16 moves it up when the entry above is movable, x > 16 and y > 16 moves it down. The Default entry (`bgh`) shows no arrows and is always last.
- Selected is shown reversed relative to the repository list (`Lists.reverse`), so the top row has the highest priority. Done builds the list from the Selected rows (reversed back), calls `setRepositories` and refreshes resources; Escape does not apply the lists.
- Entry name is the file name (`brf.d`), description the pack.mcmeta description or "Invalid pack.mcmeta (or missing 'pack' section)" (`brf.e`). options.txt stores the names as a Gson string list, lowest priority first.
- The Default entry description text "The default look and feel of Minecraft" is from memory of the launcher's default metadata, not read from the jar (the jar has no pack.mcmeta).

Batch 15 evidence (`public/research/texture-animation-reference.json`, 34 cases, from `tools/probes/TextureAnimationProbe.java` run by `tools/verify-texture-animation.mjs` against the **unchanged original classes**: `bqd` TextureAtlasSprite, `bsb` AnimationMetadataSectionSerializer; probed): `frametime` (default 1, must be >= 1), `frames` (a number, or an object with required `index` >= 0 and optional `time` >= 1; arrays and nulls are skipped), `width`/`height` (parsed, ignored by the sprite loader). **There is no `interpolate` key in 1.7.10** (it arrived in 1.9; the probe parses it away without effect). A strip is square frames of the image width, `floor(h/w)` of them; an empty list plays every frame once; an index >= the count throws "invalid frameindex"; a non-square image without an animation section throws "broken aspect ratio and not an animation". `updateAnimation`: `++tickCounter`, at the entry's time the frame advances modulo the list and the counter restarts (frame at tick n recorded for each case). The nine vanilla mcmeta files (water, lava, portal, fire layers, compass, clock...) are among the cases.

Bytecode-read, **not probed**: `FallbackResourceManager.getResource` (`bqq.a`) takes the `.mcmeta` from the pack that supplies the png or a pack above it, never from a lower pack, so a pack png without its own mcmeta hides the vanilla mcmeta. `SoundHandler` (`btp`), `SoundList`/`SoundEntry`/serializer (`bsp`/`bsq`/`bss`), `SoundCategory` (`w`): every pack's `sounds.json` is applied lowest pack first; an event that is new or has `replace: true` starts a fresh list with the entry's category (default `master`), otherwise sounds are appended and the first category stays; sound defaults volume/pitch/weight 1, type `file`, stream false; volume, pitch and weight must be > 0; categories master, music, record, weather, block, hostile, neutral, player, ambient; a missing file is skipped with a warning; one invalid entry rejects the file. `ColorizerGrass`/`ColorizerFoliage` read the colormap png as a linear `int[]` indexed `j << 8 | i`: a bigger image is read linearly, an image with fewer than 65536 pixels crashes natively.

## Implemented

- Options > Resource Packs... opens the screen (`src/resource-packs-ui.js`, hooked in `src/menus.js`). Both lists, hover arrows, move/reorder, Default entry, scrolling (wheel and bar), title/folder-info text from the lang table, Done and Escape as above.
- "Open resource pack folder" cannot open a disk folder in a browser: it opens a file picker for `.zip` packs (Shift+click: a folder via `webkitdirectory`). Zips can also be dropped onto the screen. Packs persist in IndexedDB (`mc-web-resource-packs`); there is no delete control (clear site data to remove them).
- Zip reading without dependencies (`src/zip-reader.js`): stored and deflate entries via `DecompressionStream('deflate-raw')`.
- pack.mcmeta (`pack_format`, `description` as string or `{text}`), pack.png as the icon (a bundled `misc/unknown_pack.png` otherwise).
- Selected order persists in options.txt as `resourcePacks:["a.zip","b"]` (`src/options-txt.js`, also in `blockworld.settings`).
- Loading: Done resolves the selected packs lowest to highest (top row wins), writes the winning `assets/minecraft/textures/**.png` (-> `/media/1.7.10/**`), `sounds/**.ogg` (-> `/audio/1.7.10/**` and the music stream directory) to IndexedDB and `lang/en_US.lang` to a lang table. `public/resource-pack-sw.js` (a service worker) answers requests for those URLs from the table and passes everything else to the network, so every texture user (block atlas, items, entities, GUI, particles, environment, map, CSS backgrounds) is overridden without per-file hooks. Menu strings take the pack's lang entries at page start (`initResourcePacks`).
- Refresh (batch 15): Done with a changed selection refreshes **in place** (`src/resource-refresh.js`, the `refreshResources` analogue); there is no page reload and the world keeps running. Every `THREE.TextureLoader` texture of `/media/1.7.10/**` (entity, mob, particle, first-person, strips, end sky...) is registered weakly as it loads (the module is the first import of `main.js`); a refresh re-requests each image under a versioned url (`?r=<generation>`, `src/media-version.js`; generation 0, the page load, leaves every url unchanged so vanilla is byte-identical; the service worker matches `url.pathname`) and swaps it into the texture. Stylesheet rules, `<img>` and inline-style urls get the same query so GUI sprite CSS reloads. The block atlas re-reads its images and redraws (`reload()`), the animated strips re-resolve frame count and timing, the sound manifest reloads (cache cleared), lang entries are re-applied with restore of keys the new selection no longer sets, and the spawn egg, clock, compass and achievement image caches reset. A small "Reloading resources..." note shows meanwhile; whether native 1.7.10 draws a loading overlay for `refreshResources` was **not verified**, so none is claimed.
- Texture animation (batch 15, `src/texture-animation.js`): water, lava, portal and fire strips take frame count and timing from the image size and its `.png.mcmeta` (vanilla files and pack overrides, with the hide rule above), ticked at 20 Hz like `TextureAtlasSprite.updateAnimation`. The old hard-coded phases are reproduced exactly (`texture-animation.test.js` compares 20000 sample times per strip). An invalid mcmeta falls back to the whole strip at one tick per frame and logs a warning (native shows the missing texture).
- `sounds.json` (batch 15, `src/pack-sounds.js`): replace/append, category, volume, pitch, weight, `type: event` references and `stream` for the events the game plays; pack sound files (including `stream` ones) are served from both `/audio/1.7.10/` and the streams directory.
- HD chest and colormaps (batch 15): the chest atlas rectangles scale by `image width / 64` (the entity renderer was already UV-fraction based), and grass/foliage colormaps from packs are read as the native linear `j << 8 | i` array (`src/colormap-source.js`); a too-short colormap falls back to the vanilla map with a warning instead of crashing.
- Delete control (batch 15, **not native**: 1.7.10 has no in-game delete, packs live in the `resourcepacks` folder): hover a pack row on the screen and press Delete twice to remove the stored pack from this browser; if it was selected it leaves the selection and resources refresh. This is the substitute for deleting the file from the pack folder.
- Round 3 (batch 16): `src/item-animation.js` animates pack-provided `.png.mcmeta` item textures (the items atlas is a `TextureMap`, so `TextureAtlasSprite.updateAnimation` runs for item sprites; the frame logic is the probed `texture-animation.js`). A strip of square frames is cut into data-url frames; `itemTexture()` returns the current frame, `MapsClock.tick` (20 Hz) steps every animated entry and swaps the `img.vanilla-item-icon` sources (hotbar, inventory, creative, tooltips), and the first-person held item rebuilds through a frame tag in its cache key (all frames are pre-decoded, so no blank frame). A tall non-square item strip without an animation section is cut the same way instead of being squashed (native would reject it; this keeps the screen readable). Clock and compass keep their own logic. `itemTexture()` now returns versioned urls after a refresh, so newly built icons re-request the image. Dropped items, item frames, mob and third-person held items take the frame current when they are built (they do not tick).
- Also hooked in round 3: the sky `clouds.png` grid (`Clouds.reload`), the title panorama faces (`Panorama.reload`, fresh GL textures, old ones deleted), `ascii.png` widths/`glyph_sizes.bin`/unicode glyph pages (versioned urls), the sign editor image, and clones of registered textures (end sky/portal layers, beacon beam, experience orbs register under the source url). Sun, moon phases, rain, snow, particles, steve and the other `TextureLoader` textures were already covered by the registry; the glint is registered when first used.
- HD packs: the block atlas keeps 16 px cells and draws the first square frame of any tile scaled to 16 px (`block-textures.js frameSize`), so an HD or animation-strip block texture no longer breaks or crops the atlas. Entity, GUI, item and particle textures are sampled by UV, so higher resolution there shows at full resolution.

## Verification

- Batch 16 (headless Chrome, muted, vite on 5217, CDP script not kept in the repo): a folder pack with a solid-colour `sun`, `moon_phases`, `rain`, `snow`, `particles`, `steve`, `experience_orb`, `end_portal`, six panorama faces, a 128 x 128 opaque `ascii.png`, an opaque 256 x 256 `clouds.png` and a three-frame `items/diamond.png` with `frametime: 2` was applied and refreshed with no reload. Each registered texture read the pack colour afterwards, the cloud grid went from 13356 to 65536 filled texels, the font width table changed, the title panorama turned magenta in a screenshot, and a hotbar-class `<img>` cycled red, blue, green with each frame held for two ticks. The held first-person path, a real world HUD and the dropped-item path were not exercised in a browser (only the shared module path).

- Batch 15: `texture-animation.test.js` (6), `pack-sounds.test.js` (6), `colormap-source.test.js` (3), `resource-refresh.test.js` (3), plus mcmeta hiding, applyPacks meta, deleteStoredPack and lang restore cases in `resource-packs.test.js`. Browser run (headless Chrome, muted, vite on 5203, CDP script): a folder pack with a 32 x 32 stone, a 16 x 48 water strip with `frametime: 2` and a lang file was applied and refreshed in 296 ms with the page state kept (no reload); the atlas stone tile read red, water became 3 frames of frametime 2, and removing the pack restored stone (127,127,127) and the 32-frame water; no console errors. The service worker served the pack mcmeta and answered the vanilla lava mcmeta unchanged. The first-person compass/clock HD frames, the chest and colormap paths were not exercised in a browser.

- `src/resource-packs.test.js` (11 tests): zip stored + deflate entries, rejection of non-zips, mcmeta parsing, URL mapping, override order (top wins), lang merge, pack info, `applyPacks` against an in-memory store, list arrows (bgg click rules), arrow cells/layout numbers, options.txt round trip.
- Browser run (headless Chrome, muted, vite on 5191, CDP script, not kept in the repo): a folder pack replacing `blocks/stone.png` with a 1 x 1 PNG was served by the worker (88 bytes, 1 x 1) and the bundled file (223 bytes) returned after clearing; the screen rendered both lists with three packs, arrows appeared on hover, two selections reordered the lists, Done saved `resourcePacks:["Alpha Pack","Beta.zip"]` to options.txt/settings and reloaded with the worker controlling the page. Screenshots were compared by eye to the bytecode geometry, not pixel-diffed.

## Remaining differences

- First use needs the service worker (HTTPS or localhost); a hard reload (Shift+reload) bypasses it until the next normal load. The in-place refresh covers the modules listed above; a cache not listed above keeps the old image until a page reload. Pack-animated item icons animate in the HUD and the held item but not on dropped items, item frames or other entities' held items. Animated block textures other than water, lava, portal and fire (a pack mcmeta on a normal block tile) show their first frame in the atlas.
- Compass and clock frames now follow the strip width but still assume 32 and 64 frames (their mcmeta lists are not read). Entity models other than the chest were not audited for HD pack scaling.
- The loading overlay of native `refreshResources` is unverified (see Implemented). The refresh is asynchronous with a small note rather than a blocking screen.
- The menu font is the bundled traced font, so `textures/font/*.png` is ignored. Pack fonts, shaders, `assets/<other namespace>`, pack_format mismatch warnings and folder packs with a nested `assets` root are not handled. No server resource packs. `sounds.json` entries for events the game never plays are accepted but silent; the mixer category of an event is not fed to separate volume sliders beyond what the Sounds screen already offers.
- The delete control is a web substitute (see Implemented); a pack that fails to open shows its error as the description. Not full parity.
