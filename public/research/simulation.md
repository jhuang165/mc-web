# Simulation boundary

SIM-01 has begun with `tickBlockSystems` in `src/world-tick.js`. The live player tick passes its current time, daylight and player X/Z to this browser-independent function. It advances farming, fluids and fire in that order and invokes each supplied observer immediately after its system runs. The live observers rebuild farm chunks and apply fluid/fire changes to the scene. A headless caller can supply its own observers.

`src/world-tick.test.js` runs 70 changing input ticks through the previous call sequence and the extracted function with real World, Farming, Fluids, Fire and shared Weather random state. It compares ordered observer results, blocks, farmland state, pending queues and random state on every tick; scheduled water changes and fire random draws are exercised. This is a port regression, not an original Java integrated-tick comparison.

`src/weather-simulation.js` advances the existing weather and lightning damage logic without a scene or sound dependency. The live caller invokes client rain particles and drains sound events afterward. Tests use real lightning bolts to cover repeated flashes, mob/player ordering, fire counters, powered creepers, edge contact and Creative/dead exclusions. A 160-tick headless run combines weather and block steps, saving and restoring their existing browser snapshots five times while comparing ordered changes, farmland, queues and shared random state. It uses clear weather without active lightning at reload; it does not establish active-bolt or weather-strength continuity.

`src/player-input.js` captures movement keys as plain data once per live movement tick. Its test covers all 512 relevant key combinations and records/replays snapshots through `PlayerMotion` for sprint, sneak, jump and flight rules. This is a replay of the input state machine, not player position, collisions, camera, or a complete gameplay recording.

`src/player-physics.js` now runs the live movement segment on plain coordinate objects, `PlayerMotion` and a survival state: input, water/lava, jumping, flight, ladders/webs, collision, gravity, fall tracking and finite-world handling. The browser supplies its existing vectors and continues with survival and world ticks after the movement step. Seven recorded control sequences (295 ticks) match the position, velocity, flags, motion state, exhaustion and messages captured from the pre-extraction browser code at commit `9447171`: land/wall, water/flight, lava, ladder, web, world edge and high-altitude respawn. `tools/capture-player-physics-baseline.mjs` regenerates the port traces from that pinned `main.js` and the current fixture/dependencies; review dependency changes before replacing the baseline. The trace is not original Java evidence.

`src/player-environment.js` separates the live player air, wetness, suffocation, fire and block-collision tail, plus the later movement exhaustion/landing step. It preserves synchronous hooks for weather, potion/drowning particles, fizz, trampling and landing dust; falling-block updates and display ticks still occur between its two steps. Tests exercise drowning, suffocation/cactus hurt resistance, rain/fire/web ordering, landing and Creative void damage using the real Survival class. These are port regression checks, not an integrated original-client oracle.

`src/simulation-replay.test.js` replays 180 recorded movement ticks with real Survival, falling-block, weather and block steps, checking player state, health, queues, falling entities, block edits, shared random state and ordered outputs through seven JSON checkpoints. It checkpoints both queued and airborne sand and exercises player damage, jumping, wall collision and fluid changes. Its synthetic checkpoints include transient player motion and hurt resistance and are **not** the browser save format; clear weather and no active bolts are used. The scenario does not run all of the live tick's gameplay systems.

Localhost browser smokes launched new Creative and Survival Java worlds, observed ticks advancing, walked and jumped; the browser reported no warnings or errors. They did not verify the individual environmental hazards, flight, lightning or a full gameplay/save replay.

These are segments of the existing tick, not a complete authoritative simulation. Items, mobs, projectiles, mining, most input, saves and presentation remain interleaved in `main.js`; falling blocks are still invoked there. Farming uses the supplied scene daylight. Fluid/fire callbacks can still produce presentation effects, and observers run synchronously, so callers must preserve their ordering and behavior. Separate per-system queues are not a native unified scheduler. Further work must move state ownership and effects across explicit interfaces, record/replay actual player actions and whole-world state, and compare whole ticks and browser reloads before claiming headless or multiplayer readiness.
