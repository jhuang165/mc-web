# Ender pearls (Java 1.7.10)

`src/ender-pearl.js` is a standalone behavior adapter for the original `ItemEnderPearl` (`aco`), `EntityEnderPearl` (`zm`) and shared `EntityThrowable` (`zk`). It reuses the existing `launch` implementation for eye offset, 1.5-block/tick throw speed, inaccuracy 1, gaussian heading, 0.25 × 0.25 bounds, 0.99 air drag (0.8 in water) and 0.03 gravity. Internal item 378 maps to vanilla item 368.

On impact, the native method first applies `DamageSource.causeThrownDamage(pearl, thrower)` for 0 damage to a hit entity. It then emits 32 portal particles at the pearl x/z and y + `nextDouble()*2`; each particle draws two Gaussian values for x/z motion and uses zero y motion. On the server, the pearl teleports its thrower only when the thrower is an `EntityPlayerMP`, its Netty channel is open, and its world is the pearl's world. It dismounts a riding player, teleports to the pearl's position, resets fall distance, and applies 5 `DamageSource.fall` damage. The server marks the pearl dead whether or not the owner passes those teleport gates; the client leaves it alive for server synchronization. Sleeping is not a teleport gate.

The native probe executes the unchanged impact method against server/client world doubles for no-owner and entity-hit scenarios, including 32 particle calls and their seeded RNG outputs. Six more cases run the original pearl constructor, heading, dimensions and NBT writer. `src/ender-pearl.test.js` replays launch and particle outputs against [the captured native reference](ender-pearl-reference.json). The impact teleport branch is bytecode-inspected and class-hash-bound, but the probe does not instantiate a connected `EntityPlayerMP`; fall damage, channel, same-world and dismount gates are represented as explicit adapter hooks and covered by unit cases, not claimed as live native execution.

Native throwable NBT saves the ordinary entity fields plus `ownerName`, `inGround`, `shake` and the tile coordinates; `ticksInAir` is not saved. The current browser serializer is only a JSON projection of position, motion, rotation and kind, so owner/in-ground/shake round-trip parity is open. The module is not wired to `main.js` or `projectiles.js`: integration should route `kind: "enderPearl"` through the existing projectile flight/ray-trace mechanics and call `impactEnderPearl` with the live player's connection/world state and hit, portal-particle, dismount, teleport, and damage adapters. Item consumption/sound, rendering, and live-save integration remain outside this tranche.
