# Super Secret Settings shaders and 3D Anaglyph

Target: Minecraft Java 1.7.10. Full parity is not claimed. Reference facts: [post-shaders-reference.json](post-shaders-reference.json) (jar sha1 e80d9b3bf5085002218d4be59e668bac718abbc6).

## Evidence

All of this is bytecode-read with `javap -c` from the pinned jar, not probed, because the GL calls cannot run headless.

- `EntityRenderer.shaderResourceLocations` has 22 entries (not 23): notch, fxaa, art, bumpy, blobs2, pencil, color_convolve, deconverge, flip, invert, ntsc, outline, phosphor, scan_pincushion, sobel, bits, desaturate, green, blur, wobble, blobs, antialias.
- F4 (Minecraft.runTick, key 62) only calls `deactivateShader`. It never turns a shader on.
- The Options "Super Secret Settings..." button calls `activateNextShader`, index = (index + 1) % 23, where 22 means no effect. It plays a random event from the animals, blocks, mobs, players and weather sound categories at volume 0.25, pitch 0.5, and no normal click.
- The shader choice is not saved. There are no entity or spectator shaders in 1.7.10.
- ShaderGroup/Shader: targets (name or name/width/height, `minecraft:main` is the game framebuffer), passes with intarget/outtarget/auxtargets/uniforms, program JSON (vertex, fragment, samplers, uniform defaults, blend add one/zero). Output is cleared to (0,0,0,0), depth mask off, colour mask (true,true,true,false). ProjMat is orthographic(0,w,h,0,0.1,1000); every shipped vertex shader replaces z with 0.2. Time is the accumulated partial ticks wrapped at 20, divided by 20.
- Anaglyph: pass 0 writes green and blue, pass 1 writes red. Projection shift -(pass*2-1)*0.07, eye shift (pass*2-1)*0.1. Texture and fog colour: r' = (30r+59g+11b)/100, g' = (30r+70g)/100, b' = (30r+70b)/100.
- The 22 post chains and 58 program files are extracted from the jar by `tools/import-shaders.mjs` into `public/media/1.7.10/shaders/`, with provenance entries.

## Implemented

- `src/post-shaders.js`: shader list and cycle, JSON parsing into a pass graph, GLSL 1.20 to GLSL ES 3.00 conversion (varying/attribute, texture2D, uniform initialisers moved to defaults, int/float literal fixes), the Time clock, ProjMat, three.js render targets (nearest filter) with one RawShaderMaterial per pass, and the anaglyph merge.
- Hooks: `scene.render` calls `post.begin` before the sky and `scene.endFrame()` runs after the first-person hand; F4 in `main.js`; the Options button cycles shaders with the random sound; 3D Anaglyph in Video Settings is enabled and persists as `anaglyph3d` in options.txt.
- Tests: `src/post-shaders.test.js` (chain parsing for all 22, program parsing, conversion checks for every program, cycle/F4, clock, projection, anaglyph constants and formulas, sound categories, options persistence).
- Browser check: a headless Chrome (SwiftShader) harness cycled all 22 shaders on a test scene with no shader compile errors or GL errors; outputs changed as expected (invert, green, sobel and others). Anaglyph output matched the colour formula on the test scene. This was a synthetic scene, not a full in-game session.

## Remaining differences

- 3D Anaglyph (batch 27) now converts at the native points: `src/anaglyph.js` wraps `texImage2D`/`texSubImage2D` while the option is on (TextureUtil.anaglyphColor, `bqi.b`, so atlas, mips, dynamic and lightmap uploads all convert; render-target allocations do not), fog, sky and cloud colours use `anaglyphFog` (`updateFogColor`, RenderGlobal), and the merge shader is a pure channel mask (eye 0 -> G,B; eye 1 -> R). Toggling the option calls `refreshResources()` like `GameSettings.setOptionValue` (`bao.c()`, bytecode-read). The previous final-pixel method is kept as `post.legacyAnaglyph = true`. Earlier text claiming the lightmap is not converted was wrong: it goes through the same upload funnel. Same scene, three frames (`artifacts/b27-atlas2/anaglyph-*.png`, stats in `anaglyph-stats.json`): native vs legacy mean abs RGB difference 2.19 of 255, max 75 (blended edges and tinted surfaces); mean RGB off [117.0,127.8,138.5], legacy [125.9,124.6,132.8], native [124.0,125.5,131.7]. Not ported: RenderBlocks vertex colour conversions (13 `blt.a` sites, e.g. biome multipliers: biome tints are still unconverted before masking), the FontRenderer colour-code table, sunrise colours, and the DOM GUI (never converted by either method).

## Batch 28: RenderBlocks colours, sunrise, reader inventory

Every native reader was found by `javap -p -c` over all 1803 classes (bytecode-read; the classes need a live Minecraft so they were not run). `EntityRenderer.anaglyphEnable` (`blt.a`) is written once, in `blt.b(float)` from `GameSettings.anaglyph` (`bbj.e`), and is read only by `blm` (RenderBlocks) at 13 sites: `q` renderStandardBlock, `l` renderCrossedSquares, `t` cactus, `m` stem, `k` render type 41, and the double plant, pane, anvil, brewing stand, cauldron, flower pot and two hopper methods. Direct readers of `bbj.e`: `bqi` texture upload, `bbu` FontRenderer constructor (colour table, text2 track), `bma` RenderGlobal (sky @318, sunrise @566, clouds in `b`/`c`, colour masks, a chunk-update skip @515) and `blt` (eye shifts, per-eye loop, `j` updateFogColor). Nothing else reads it: no star, item, lead, beacon, entity or particle conversion exists. Full list: [anaglyph-colors-reference.json](anaglyph-colors-reference.json).

Ported: the mesher converts the block colour multiplier (`Mesher.tint`, `anaglyphMultiplier`, `meshAnaglyph` in `src/anaglyph.js`) for cubes (grass, leaves), the grass side overlay, tall grass/fern/reeds/double plant and stems. Paths that never read the flag keep raw tints: water (`blm.p`), vines, lily pad, redstone wire. Toggling marks every chunk dirty (loadRenderers). The sunrise fan converts only the centre vertex (`bma.a` @566); the rim keeps the raw RGB at alpha 0. Probe: `tools/probes/Anaglyph2Probe.java` (Java float arithmetic of the read expression).

Still open: the FontRenderer colour table, the DOM GUI, held/dropped block item colours in the first-person hand (not read natively either), and the `bma` @515 chunk-update skip.

## Batch 29: DOM GUI conversion, toggle timing, chunk-update skip

DOM GUI (`src/gui-anaglyph.js`, `src/png-codec.js`). Natively every GUI texture reaches `bqi.b` and is converted at upload while `GameSettings.anaglyph` is set, so the whole GUI (widgets, containers, icons, item sprites, entity skins in GUI) is converted and never eye-masked. The port draws most of its GUI as DOM, so while 3D Anaglyph is on the stylesheet URLs, inline styles, `<img>` sources and canvas-screen images under `/media/1.7.10/*.png` are rewritten to converted data URLs. The conversion uses the same integer formula as `src/anaglyph.js` and is exact on translucent pixels: an own PNG codec is used instead of canvas `getImageData`, which round-trips through premultiplied alpha. Converted copies are cached per source path and media generation, converted URLs carry `#mcag=<path>` so they can be restored, and a MutationObserver runs only while the option is on. There are no CSS filters. Declarations are rewritten from `style.cssText`, because a shorthand that holds `var()` reports empty longhands. The paperdoll, horse preview, enchanting book and panorama WebGL contexts use `installAnaglyphUpload` with the shared state.

Toggle timing. Native `setOptionValue(ANAGLYPH)` calls `refreshResources` (`bao.c()`) synchronously. The port goes through `refreshResources`, which now also prepares and rewrites the GUI images; this is asynchronous (a short delay while PNGs are decoded and converted). Previously the toggle was noticed only in `post.begin` during world rendering, so toggling on the title screen did nothing; `PostShaders.syncAnaglyph()` from `scene.setRenderSettings` fixes that.

Native pixel evidence. `tools/verify-anaglyph-gui.mjs` runs the unchanged `bqi.a(int[])` (`TextureUtil.anaglyphColor`) from the jar over 263 textures (gui, items, misc, steve and chest skins, dirt) through `tools/probes/Anaglyph3Probe.java` (with a no-op GL11 stub) and writes `anaglyph-gui-reference.json` (SHA-1 of raw and converted ARGB, 13 textures with translucent pixels). `src/anaglyph-gui.test.js` converts the same files with the port's code and compares hashes (exact match).

Chunk-update skip (`bma.a(sv,int,double)`, sortAndRender @515, bytecode-read). The branch is `D && bbj.f(advancedOpengl) && !bbj.e && pass == 0`, where `D` is occlusion-query availability: with anaglyph on, the occlusion-query path is not taken and all chunks are rendered. The port has no occlusion queries and Video Settings has no Advanced OpenGL option, so the port already always takes the render-all path. The skip is therefore not observable and is not modelled.

Browser check (headless Chrome `--mute-audio`, `?silent`, `artifacts/b29-anaglyph3/`): on the title screen and in a world, with anaglyph forced on, 53 stylesheet rules were converted and none stayed raw; switching off restored all with the `?r=` generation. Hearts convert to grey (76,76,76) and the paperdoll skin desaturates, as expected from the formula.

Limits. Grass and leaf tints are baked into the atlas before conversion (native converts the texture then multiplies the raw tint). Resource-pack icon blob URLs and the profile screen `steveSkin` are not converted. Pending images show transparent for a moment after toggling and first-seen inline styles may flash raw. The legacy anaglyph mode leaves the GUI unconverted. The canvas-based GL upload hook still rounds translucent pixels for Image sources. Not eye-masked: GUI is drawn once, as natively.
