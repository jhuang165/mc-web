# ringlight2 b30 track (ring rim light, window edits beside ring columns, server vs client light)

## Summary
- Rim: `computeColumnLight` and the `RingLight` search treat a neighbouring chunk that is neither resident nor held as an unloaded barrier (no seeds, emitters, receiving or carrying). The `complete()` gate for bulk light is removed; rim columns are bulk-lit and re-lit when a neighbour arrives. Model, not native-exact (native rim light is vertical-only and lazier).
- Resident edits: `world.js` `put` calls `ringSink.edited(x, z)` (the only world.js change, one line); `HeadlessColumns.edited` drops bulk light, `asked` and the search cache for held non-resident columns in the 8 chunks around the edit.
- Server vs client: `tools/probes/LightClientServerProbe.java` runs the unchanged `ahb`/`apx` with a server world (o + func_150804_b per tick) and a client copy (packet light, no empty sections, no func_150804_b); 8 records, about 100 edits. Block light and heights never differ; sky differs in empty sections right after the packet (288-512 cells in the probe layout) and by 9 cells under the first floating slab block. Not ported (documented in light-engine.md "Batch 30").
