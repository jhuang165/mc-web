# Batch 68 chunkscan2: farming on random ticks, treeified HashSet bins, exact End origin

## Summary
- `src/farming.js`: `Farming.randomTick(x, y, z, b, random)` (farmland -> `soilTick`, crops and stems -> `grow`, the growth roll through the world's `java.util.Random.nextInt`); `sharedRandomTicks` makes `tick()` only drain. `grow` takes an optional `nextInt`.
- `src/multiplayer/simulation.js`, `server-nether.js` (Nether and End): `farming.sharedRandomTicks = true`, `farming.random` / `stemRandom` = the dimension's weather random, and `farming` added to `weather.blockTick` after fire, trees, plants. Farmland, crops and stems now tick only in the players' active chunks; with nobody in a dimension nothing grows there.
- `src/java-hashmap-tree.js` (new) and `src/java-hashset-order.js`: Java 8 treeified HashMap bins (treeify, putTreeVal, moveRootToFront, split/untreeify on resize). `ChunkSet.order` is now exact for overlapping players.
- `src/multiplayer/server-chunks.js`: the set is built from NATIVE chunk coordinates (player chunk = floor((local + origin) / 16)); a native chunk that straddles the local grid (legacy End, origin -25 / -96) is returned as `[cx, cz, dx, dz]`. `src/weather.js` `tickChunk(world, cx, cz, dx, dz)` draws cells from that offset and checks the sections of the overlapped local chunks. The full End (origin -128) and the other worlds still return `[cx, cz]`.
- `tools/probes/ActiveChunksProbe.java`: new cases `cluster`, `crowd`, `negcluster`, `radius7`, `long`; `public/research/active-chunks-reference.json` regenerated by `tools/verify-active-chunks.mjs`.
- Tests: `src/chunkscan2-b68.test.js` (8). No new wire messages.

## Evidence
- Executed: all 11 ActiveChunksProbe cases (real `agu` in a real HashSet, JDK 19, several ticks with the table kept) replay exactly, including `two` and `cluster`, which contain a treeified bin (the b67 note called that a limit; it is closed).
- Bytecode-read in b67 (not re-read): ahb.C fill, mt.g iteration, agu.hashCode.
- Recalled (OpenJDK 8 HashMap.TreeNode source): treeify, putTreeVal, balanceInsertion, rotate, moveRootToFront, split. Validated only through the executed cases above. Java 7 mode has no trees.
- Recalled: BlockFarmland, BlockCrops and BlockStem tick on random block ticks (they are `setTickRandomly(true)`); fire (BlockFire) and saplings were ALREADY on the shared random loop on the server (`fire.sharedRandomTicks`, `trees.randomTick`); the server never called `Trees.tick` or the fire scan. So the only server own-scan was `Farming.tick`. Fire's scheduled ticks stay on the tick queue, as natively.
- Not modelled: removal from a treeified bin (`treeRemovals` counts it; only set and clear exist for chunk sets, and trackers never reach 9 ids in a bin); equal full hashes of different keys (native uses identityHashCode; `ties.count` stays 0 in every executed case).
- Legacy End window: cells of a straddling native chunk outside the window are unknown; their draws still consume the lcg and hit air. A section counts as ticking when any overlapped local chunk's section does (the outside is End stone natively, which does not tick).
