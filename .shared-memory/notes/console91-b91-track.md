# console91 (batch 91): owner strings, name tags and later watcher keys in S0F / S1C; vehicle and object packets under their own ids; light hash cost

## Summary
- **Owner strings and name tags.** `src/multiplayer/net-watch-bytes.js` (new) derives a live mob's native watcher entries (`watchState`) and the bytes its strings add over the empty strings of the class table (`stringExtra`). `net-packet-ids.js` `mobRecords` adds them to the S0F and to the whole-DataWatcher S1C that follows a spawn. A tamed wolf, ocelot or horse (36 characters, a player's UUID text) is 36 bytes longer; a name tag is its UTF-8 length longer, plus one byte once past 127 bytes (two-byte VarInt).
- **Later S1C keys.** The server remembers, per receiving connection, the state it last counted for each mob (`ws.netWatch.memory`, set by the spawn). When a `mobs` message carries a packet of a mob, the entries that differ now (health 6, age 12 (zombie: baby byte), wolf 16/17/18/19/20, ocelot 16/17/18, sheep 16, pig 16, villager 16, creeper 17, slime 16, horse 19/20/21/22, name 10) are counted as one S1C (`id + int + entries + end byte`). Keys the port's own meta packets already carry (air, potion, flags, screaming, invul, wither/dragon health, bat hang, horse flags) are not derived twice. `server/server.js` supplies the lookup (`ctx.watch`: Overworld mobs by wire number, rebuilt once per tick; a player in another dimension gets none).
- **Vehicles.** `server-cart-track.js` records the packet kinds each cart/boat entry released in its tick (`en.kinds`); `server-vehicles.js` attaches them (plus `join`, the S0E data, S12) to each `vehicles` set row through a WeakMap (`setVehicleInfo`, nothing on the wire; each row is now its own copy). `vehicleRecords` counts S15 / S16 / S17 / S18 / S12 per kind, an S0E (+6 bytes when the cart type is above 0) with the spawn's S12 on a join, and one S1C int entry (11 bytes) when only a watched field changed. A row without info still counts one S18.
- **Objects.** `itrack` rows (items, XP orbs: `tick` message) and `trk` rows (`dispEnts`: falling blocks, arrows, thrown entities, hooks, rockets, eyes) were not counted at all beyond the S0E of `ents`. They now count each tracker packet under its own id: S0E (+6 when data > 0) or S11 for an orb, S1C from the watcher list (entry sizes by type, exact for strings and ItemStacks), S12, S15, S16, S17, S18 and the tick's destroys as one S13.
- **Light hash.** `tools/bench-lighthash91.mjs` (node only). `hashSide` is exported for it. No change to the hash.
- **Probe.** `tools/probes/Console91Probe.java` (copy of Console90Probe) via `tools/verify-console91.mjs` -> `public/research/console91-reference.json`. The entity id counter (`sa.b`) is reset per class so S0F's entity-id VarInt stays one byte, as in console90.

## Evidence
- **Executed (Console91Probe, unchanged jar):** `et.a(String)` sizes (0 chars 1, 36 ASCII 37, 3 x e-acute 7, euro sign 4, 200 chars 202). The public one-String setters that fill a watched string, found by reflection over all 29 living classes: `sw.a(String)` (name tag, index 10, every class), `tg.b(String)` (owner, 17, wolf and ocelot), `wi.b(String)` (owner, 21, horse). S0F with a 36 character value: Wolf 102 (66 + 36), Ocelot 95 (59 + 36), Horse 108 (72 + 36), Pig 91 (55 + 36). One changed float (index 6) or int (index 12) in `hw(id, dw, false)` is an 11 byte S1C for every class that has the key; writing the same value again is not marked changed (`te.b` compares). Per-class watcher keys (index and type) are `spawns[].entries` in the reference (all 29 classes).
- **Bytecode-read:** `rx` (EntityAgeable) `e()` calls `c(int)` = `te.b(12, age)` each living update while age is not 0, so babies and animals in breeding cooldown change watcher 12 every tick; `rx.c()` registers 12 as an int. Tracker packet choice for carts, boats, items, orbs and falling blocks is `EntityTrackerEntry.sendLocationToAllClients`, already run by the port's `TrackerEntry` (executed in `tracker-vehicles-reference.json`, `tracker-items-reference.json` in earlier batches); this batch only counts its packets by kind.
- **Port-read:** which port fields stand for which native keys (`watchState`: `growingAge`, `owner`, `customName`, `sitting`, `angry`, `collar`, `catType`, `color`, `sheared`, `saddled`, `profession`, `powered`, `size`, `horse.*`); the S0E data of items (1), orbs (S11), falling blocks (id | meta << 16), carts (type).

## Verification
- `node --test --test-concurrency=2 src/console91-b91.test.js`: 6/6 pass. With `net-packet-ids.js` stashed it fails 4 of 6.
- The tests of the files touched or naming them (console86/88/89/90, offline87, mp*, tracker83, carts, accounts, client-screens, multiplayer, pvp-b63, rain83, seat86 ... 40 files): 400/400 pass, no old test changed.
- Light hash, `node tools/bench-lighthash91.mjs 128 256` (a shared, busy Mac): about 0.09 ms per column (0.42 ms for a 5 column S26), 3.1-3.3% of what a cache miss costs (build + deflate 2.7 ms a column). Not optimised: a cache hit still saves 97% and a 400 column join is about 35 ms of hashing once. A cheaper key would need a dirty counter in `LightVolume`, which it lacks.
- `npm run build` once: ok. No full `npm test`, no browser.

## Found wrong in the batch 90 list
- "the light hash cost is unmeasured": measured above, small.
- Item, orb and falling-block tracker packets were not "counted as S18": they were not counted at all (`itrack` and `trk` have no entry in the bundle tables), except the S0E of `ents`. Carts and boats were counted S18 as stated.

## Follow-ups
- The S1C of changed keys is counted only when a `mobs` message already carries a packet for that mob: a mob that is still while its age or health changes is counted at its next packet (an undercount). The creeper's state/ignited, enderman carried block, wither target ids, horse flag-like bytes and the villager's mating state are not derived. Mobs of the Nether/End get class defaults (no lookup there).
- Owner text is counted as 36 characters (a player's UUID); a foreign imported owner string of another length is not.
- A cart's S12 that is not released as `motion` (carts) is not in the vehicle row, so it is not counted; the first S1C after a cart/boat join is not counted.
- `dispEnts` `ents` (TNT, fireball snapshots) still count one S0E per tick per entity: they are the port's per-tick snapshot rows, not packets.
- Browser-only: nothing visible changes.
