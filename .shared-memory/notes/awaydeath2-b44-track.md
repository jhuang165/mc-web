# awaydeath2 (batch 44)

## Summary
- **Lost deliveries: found, not a loss.** The batch 43 trip put its portal in a column the away run had not copied. Entities there are kept as saved and do not tick, so nothing went through the portal in the run; the returning player arrived beside the portal, collected the item and an orb, and the pig and two orbs travelled live. Evidence: the lead's script (`artifacts/b44-awaydeath2/away-lead.mjs`, instrumented) logged `dep` (live portal departures after the return, `busy:false`) and, in the Nether before returning, the copied chunks: the portal cells read `nocol` in every failing run. 7 of 28 completed lead-script runs failed this way (one more aborted). The 4 traced for columns showed `nocol` (runs 10, 12, 22, 23); run 5 was outside the 32-block rule (native rule, correct); runs 2 and 4 were not traced but show the same live deliveries. Not reproduced: a loss by any other route (orb merge, item age, shadow pickup); the away run has no player and the run lasts at most a few hundred ticks in these trips.
- **Fix 1, ring columns.** `src/headless-columns.js` `fullColumn`; `src/main.js` `chunks` (small edit) copies a column the ring holds when the window does not. Checked in the page: for non-resident ring columns the copy equals `ring.get` for every cell.
- **Fix 2, the column cap.** `src/away-plan.js` `MAX_COLUMNS` 64 -> 160, and work columns sort before halos. In the failing run 22 the plan hit the old cap (64 of 64) and cut the portal's column even though the portal was inside the 32-block rule.
- **Instrumentation.** `entities.counts.outside` (away-entities.js) = records kept as saved because they were not in the run; it shows in `dims.awayLog.entities`. A missing delivery now has a number to check first.
- **Death screen.** Decision, no code change in behaviour: it stays at the return. The run is computed at the return from the live player's trace, so a kill cannot be forwarded as it happens without a continuously running worker. `placeAwayDeath` now returns the death `tick` (log only). Documented in `public/research/dimensions.md` "Batch 44".
- **Uncopied columns.** Rule: the entity's column, its eight neighbours (halo), and ring columns are copied up to 160; beyond that, or outside the ring/spawn area/32-block rule, entities keep their saved state. Native evidence: unchanged from batch 43 (bytecode-read `checkChunksExist`); nothing new executed, so no probe or reference changed.
