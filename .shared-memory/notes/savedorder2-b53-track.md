# savedorder2 (batch 53)

## Summary
- Section/chunk moves: `trackSections(mobs, order, start)` in `src/saved-order.js` runs the check of World.updateEntityWithOptionalForce at the start (notes where each entity is filed) and end of every `EntityWorld.tickMobs` pass (two one-line hooks in `src/entities.js`). An entity whose floor(posX/16), floor(posY/16) or floor(posZ/16) differs from its filed cell gets a stamp (`mobs.sectionSeqs`) above everything so far, which the save walk uses for the order inside a section; the loaded-list order (`orderSeqs`) is untouched, as natively (only Chunk.entityLists change). The comparison is the unclamped section against the clamped filed one, so an entity at y >= 256 or y < 0 is refiled every pass (executed). Chunk order uses the place of a chunk's first entity seen (`mobs.chunkBirth`), so a mover arriving later does not reorder chunks.
- Mounts: natively the rider is the record (its `Riding` compound holds the mount, Entity.writeToNBT) and the mount is skipped (writeToNBTOptional returns false when riddenByEntity != null). The loader adds the rider, then each mount of the chain, to the chunk it is reading, filed by the mount's own posY/16. `saveWalk` now returns that load order (`loadOrder`), so `ord` of a mount follows its rider's record, in the mount's own section.
- Fireballs and wither skulls are stamped (`ballGroup` in `orderGroups`: the dimension's records, fireballs then skulls, as `serialize` writes them); `src/away-entities.js` serializes them before the stamp (`run.fireballs`), restores them with the other groups, and counts the other-dimension records in the base. `main.js` needed no change (`mobs.world.dimension`).
- `removedHealth` is now set for the cured zombie (`cureZombie`) and the sheared mooshroom (`mooshroomInteract`). Readers (`grep removedHealth`): only the replay harnesses (`legacy-ai-replay`, `enderman-wolf-replay`, `village-fight-replay`, their `removedHealth ?? health` state rows and the village-fight arrow-target filter); tracker S1C health, `/kill` and the away runs never read it (corpses are filtered by `health > 0` and are not tracked), so `health` stays 0 for the corpse as before. The villager a zombie kills already has health <= 0 natively; the Wither/peaceful/creeper cases are unchanged.

## Follow-ups
- The section check runs at the end of the pass for all entities in list order (natively right after each entity's own update); an entity moved by another entity after its own turn is refiled one pass later than natively. Chunk load order is still approximated (first entity seen).
- A cow saved at y > 256 is not restored by the away run's loader (and a cow at y -20 is placed after the stamped ones): the loader's treatment of out-of-range mobs was not examined; the probe scenario uses in-range cows.
- A cart carrying the player is written under the player's `Riding` natively, not in the chunk list; the port still saves it as a cart record.
- `removedHealth` is only read by replays; a mob that natively keeps its health on setDead elsewhere (zombie villager kill conversion, siege and other `health = 0` removals) was not audited.
