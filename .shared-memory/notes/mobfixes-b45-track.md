# mobfixes (batch 45)

## Summary
- **Ocelots on chests and furnaces.** Two new executed records in `enderman-wolf-b44-reference.json` (`b45mf-ocelot-sit-chest-6361`, `b45mf-ocelot-sit-furnace-6362`, 54 records now; the 52 older records are byte-identical). The unchanged `EntityAIOcelotSit` (uw) runs on the probe world, which now answers `getTileEntity` for a chest cell with an allocated `TileEntityChest` (users 0); the lit furnace (block 62) needs no tile entity. Every draw of the cat (the 0.65% `nextDouble`, `nextInt(nextInt(1200)+1200)+1200`, wander) replays exactly; the port needed no change except the replay giving `ocelotBlocks.furnaceLit` for block 62. Only bytecode-read: the chest lid refusing to open under a sitting cat (`BlockChest.o`, covered by `ocelot.test.js`); no record opens a chest.
- **Piston push order.** `pushMove` (TileEntityPiston -> `Entity.moveEntity`, sa.d) now emits the landing (fall damage, dust) before the step sound, as `moveWith` does. Evidence: both paths are the same native method, and the walking order is executed in the b44 records. No probe pushes a living mob with a piston (PistonLiveProbe uses item entities), so the order for a pushed mob is by construction of the shared method, not a separate record.
- **Golem and blaze 1e-7.** Cause: the blaze's strafe branch (`td.bq`) computes its yaw with `/ 3.1415927410125732D` (float pi as a double) and `silverfish.js` used `Math.PI`, one float step off at one tick; the strafe `-sin(a) * moveForward` carried that into the velocity (4e-9). Fixed to the float constant. Layout 4517 (blaze 1.5 east, 3 up, player at 54.5/60.5) is now recorded as `fb43-golem-blaze-4517` (28 records, the 27 others identical). The sweep of seeds 4476 and 4517 over 3 player spots x 17 distances x 4 heights x 2 angles replays exactly after the fix, except the layouts below. I could not recover the exact 4476 layout of batch 43 (not in a grid I could reproduce), so it is not recorded; no 1e-7 divergence is left in any layout I tried.
