# summon86 (batch 86): /summon spawn order and the Invulnerable save round-trip

## Summary
- **onSpawnWithEgg order (item 1): fixed for the command path.** `bu.b` (bytecode-read, offsets 239-301): `createEntityFromNBT` (the Entity constructor takes the next id), `setLocationAndAngles` with the yaw readFromNBT left (0), `onSpawnWithEgg(null)` when untagged and living, then `spawnEntityInWorld`. The extras onSpawnWithEgg spawns therefore enter the world list *before* the summoned mob: the ocelot's two kittens (`wn.a(sy)`: `world.rand.nextInt(7) == 0`, two `new wn`, `setLocationAndAngles(.., rotationYaw, 0)`, age -24000, spawn), the spider jockey's skeleton (`yn.a`: `world.rand.nextInt(100) == 0`, skeleton rolled, spawned, mounted) and the chicken jockey's chicken (`yq.a`: child -> `world.rand.nextFloat() < 0.05` nearby chicken, else `< 0.05` a new chicken rolled, flagged, spawned, mounted). Their ids follow the summoned mob's. Executed (new `Summon86Probe`, 10 kinds, World.rand seeded per run): every recorded run matches the port's list order, relative ids, riding links, World.rand's next long after the command, sheep colour, villager profession, zombie/pigman child and villager flags, kitten age. `command-host.js` now runs `create`, `entitySeed`, `onSpawnWithEgg`, then pushes the mob (the old `spawnNatural` pushed first). SpawnerAnimals and the spawn egg keep `spawnNatural`/push-first (their native order: spawn, then onSpawnWithEgg). Horse variant, zombie gear, skeleton gear, CanPickUpLoot draw Entity.rand (unseedable natively: `new Random()` per entity), so only their World.rand effect is compared (none: World.rand is untouched for skeleton, chicken, horse, pig).
- **Invulnerable (item 2): saved and loaded for every kind.** Bytecode-read: `sa.e` (Entity.writeToNBT) writes `Invulnerable` (`sa.i`) unconditionally; `xk`, `sq`, `ss`, `tb` (painting), `st` (frame), `su`, `xi`, `xl`, `wz`, `xj`, `sv`, `sw` do not override `e(dh)`. So items, orbs, paintings, frames, boats, carts and mobs write it. Port: `item-entities.js` serializeOne/load, `experience.js` orb load (strip already kept it), `hanging.js` toJSON/load, `boats.js` and `minecarts.js` serializeOne/fromJSON (one key each), Java export `entity()` writes the record's flag (was always 0 apart from crystals), Java import reads it for items, orbs, hanging, boats, carts and mobs (`entity-uuid.js invulnerableFields`). Mob browser records already carried it; `summonedMobRecord` now sets it and no longer reports `Invulnerable` as ignored. Leash knots: `su.d` (writeToNBTOptional) is false, knots are never saved; an invulnerable summoned knot now refuses hits (`ss.a` tests `aw()` first; `horse-gear-live.js knotAttack`).
- **Other dropped tags (item 3).** Item `Health` (read & 255 since b85) was lost on save (reload gave 5): saved when not 5, loaded & 255; the Java export writes `(short)(byte)health` for items and orbs (`xk.b`, `sq.b`: `i2b i2s`; was a constant 5 for items) and the import reads it. Item `OnGround` is saved. `/summon` now reads an orb's `Age` (`sq.a`: getShort) and an item's `Owner`/`Thrower` (they were reported "not kept" though the live item has them).

## Follow-ups
- Primed TNT and falling blocks do not save Invulnerable/OnGround/FallDistance in the browser save (`main.js` tnt records, `falling.js`); nothing damages them, so only the Java export differs (writes 0).
- Item `Age` is clamped to 0 or more on summon and import; native `getShort` keeps a negative age (the item lives longer).
- A summoned mob's `rotationYawHead` keeps the constructor's Math.random yaw natively (readFromNBT sets only rotationYaw); not checked.
- Browser-only: nothing new (list order affects tick order and the tracker's entity order; no visual).
