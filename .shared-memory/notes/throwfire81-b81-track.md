# throwfire81 (batch 81): throwables and fire

## Summary
- Arrows in lava: `Arrows.step` (`bow.js`) now sets `velocityChanged` on every tick the arrow's shrunk box is in lava, with fire = max(fire, 300). EntityArrow (zc) does not override `attackEntityFrom`, so setOnFireFromLava's `attackEntityFrom(lava, 4)` reaches Entity.attackEntityFrom, which runs `setBeenAttacked` (`velocityChanged`). The single-player object tracker (`object-tracker.js`) sends the arrow's S12 from that flag, as it already did for the 20th-tick fire flag. A client copy (`ctx.remote`) now zeroes its counter every update (sa.C), takes 300 again in lava, and a hit from that copy reads `clientBurning || fire > 0` (sa.al: the counter or the watched flag). The dedicated server sends arrows as `dispEnts` snapshots with positions every tick, so the flag has no wire effect there. It now adds `f: 1` to a burning arrow's or ball's row (see below).
- Thrown potions and bottles o' enchanting: they already went through `Projectiles.step` (the fluids80 fire part: water zeroes the counter, a client copy zeroes it, lava sets 300 and flags `velocityChanged`, the counter runs down with the flag every 20th tick). Their save layer dropped the counter. Now `WitchPotions.serialize`/`load` keep `fire`, which also covers the dedicated server's lanes (`server-dispense.js` save/load go through them). `java-projectiles.js` imports the `Fire` short of ThrownPotion and ThrownExpBottle, and `region-export.js` writes Fire for the `thrownPotions` list. `ProjectileRenderer`'s `THROWN_FIRE` now includes `potion` and `expBottle`.
- Fire overlay on other entities: the new `src/fire-overlays.js` (`FireOverlays`, `FIRE_BOXES`, `entityBurning`, `cameraViewYaw`) keeps one `EntityFireRenderer` per burning entity of a renderer's list. It is used by `DropRenderer` (items: 0.25 box, yOffset 0.125), `ArrowRenderer` (0.5, 0), `ExperienceRenderer` (orbs: 0.5, 0.25; main.js now passes the scene for the camera) and `BoatRenderer` (1.5 x 0.6, 0.3). `objectView` sets `burning` for item, orb and arrow views from the copy's watched flag 0. Arrows and throwables also read the copy's own counter, which lava sets during the copy's update. `vehicleView` sets it for boats. Without a copy the live counter (`fire > 0`) decides.
- Dedicated multiplayer: `client-itrack.js` rows carry `b: 1` from the copy's flag 0, which main.js `syncMultiplayerItems`/`syncMultiplayerOrbs` turn into `burning`. The `dispEnts` arrow and ball rows carry `f: 1` while the server counter runs, and `RemoteDispense` sets `row.burning`.

## Evidence
- Bytecode-read (javap -c -p on the unchanged 1.7.10 jar):
  - `zc` has no `a(ro, float)` override. `sa.a(ro, float)` returns false if `aw()` (invulnerable), else calls `Q()` (`H = true`, velocityChanged). This corrects fluids80's guess that EntityArrow overrides attackEntityFrom.
  - `sa.E` (setOnFireFromLava): unless `ae` (isImmuneToFire), it calls `a(ro.c, 4.0f)` then `e(15)`. `sa.e(int)` sets fire to max(fire, seconds * 20, after agi.a). `sa.C` calls `P()` (handleLavaMovement) and then `E()`. `zc.h` begins with `sa.h`.
  - `sa.aA` (canRenderOnFire) returns `al()`, which is isBurning: `!ae && (e > 0 || (world.isRemote && getFlag(0)))`. A `javap -p` sweep of all 1782 top-level classes finds one override, `xj.aA` (EntityFallingBlock), which returns false. `bno.b` (doRenderShadowAndFire) calls `a(sa, DDDF)` (renderEntityOnFire) when `aA()` holds.
  - `xk` (item), `sq` (orb), `zc` (arrow) and `xi` (boat) call `sa.h` in their `h()`. `xw` (primed TNT) and `xl` (minecarts) do not, so they never set flag 0 and are not given overlays.
- Port-read: the overlay boxes (width, height, posY - minY) come from the port's entity sizes and yOffsets (`OBJECT_KINDS`). The view yaw comes from the camera's world matrix (renderEntityOnFire's `-playerViewY`, matching the projectile renderer's `180 - yaw`).
- No new executed probe. The arrow lava S12 is inferred from the bytecode plus the existing executed `tracker-hits-reference.json` arrowFire path, where the tracker sends an arrow's S12 from `velocityChanged`.
