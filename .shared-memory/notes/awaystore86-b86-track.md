# Batch 86 awaystore86: away-run game rules and tile stores (signs, beacons, pots, note blocks, table names)

## Summary
- Game rules in the away run: `runAway` now sets the `game-rules.js` source to the run's own rules (the saved `plan.gameRules`, then whatever a /gamerule in the run leaves; `awayCommands` returns `rule(name)`) and puts the previous source back in a `finally` (`setGameRuleSource` now returns the old source). The worker used to read the 1.7.10 defaults, so doTileDrops, doFireTick and mobGriefing saved as false were ignored there (LiveRedstone's crush, fire, entities all read `gameRule`). The body has no await, so nothing else reads the source during the run.
- doTileDrops: one `dropBlock` helper in `away-world.js` (gated, 0.7 spread via the run's item random). The skull break (`installSkullBreak`), /setblock's pot plant (`dropStacks`), the fluid wash/burn and the new support-loss pops use it. The fluid wash now drops what `washStacks` says (as main.js: string for cobweb, crop drops, pot + plant), not the washed block's own id at +0.5/+0.25. /setblock destroy and the dispensed bucket's `breakBlock` keep their old drop (block id at +0.5/+0.25) but are now gated (`destroyBlock`).
- Tile stores: the plan carries `signs`, `beacons`, `pots`, `musicTiles`, `totalTime` and (only when saved) `player.tableNames` / `player.enderTiles`; the run returns signs/beacons/pots/musicTiles (and the named maps through `tiles`), and `dimension-live.js` writes them back (empty list -> key deleted) and passes `totalTime: this.clock(root)`. A world.onChange hook removes a sign/beacon tile on any change of that cell and makes a fresh one for a new sign/beacon (native, see Evidence); table names and ender-chest tiles go with their block. `restorePots` loads `world.pots`, so a washed, crushed or replaced pot drops its plant. `rt.restore` gets `musicTiles` (note pitch, jukebox record).
- Beacons tick: `tickBeacon` per tile in a ticking column while the entity gate is open, when total time `totalTime - (ticks - n - 1)` is a multiple of 80 (falls back to `plan.time` + time shift without a total time). Players list is empty (none in the Overworld), so only Levels changes. `stateColumns` adds beacon columns only when the run has other work.
- Support loss: `watchSupportLoss` (multiplayer/server-support-loss.js) is installed on the away world after the tile hook, so a sign (and flowers, crops, ladders, snow, carpets) whose support goes pops with its item under doTileDrops; a refused write drops nothing.
- /setblock in the run writes the run's own stores: `awayCommands` takes `stores` (signs, skulls, beaconTile) spread into the command env. Before, a /setblock skull went to the module-level SKULLS store and sign/beacon tags went nowhere.
- Fixed a b84 regression: a `//` comment in the redstone game object swallowed `sound`, `markUnsaved`, `player`, `mobs`, `commandHost` (only `commandHost` mattered; `installCommandBlocks` calls `game.commandHost()` unguarded). I made the same mistake once in the return object while editing and fixed it; worth grepping for `// .*\w+: ` swallowing in long lines.
