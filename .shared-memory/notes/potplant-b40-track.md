# Batch 40 potplant track

## Summary
Branch `batch40-potplant`. The executed RenderTypes2 record now covers the flower pot plant, connected stems, iron bars and position-hashed drawing, and every fixture is exact: the `KNOWN` table in `src/render-types-2.test.js` is empty (was one row, `140:33`).

- Flower pot: the pot's plant never drew because the probe never ran `Item.registerItems` (`adb.l()`), so `Item.getItemFromBlock` returned null and `renderBlockFlowerPot` skipped the `instanceof ItemBlock` check. With `adb.l()` the tile entity resolves for all 14 contents (every flower, sapling, mushroom, cactus, dead bush, fern). `src/render-vessels.js` already matched the plant geometry; the only gap was the fern's colour (the plant block's `colorMultiplier`, the grass colour at the pot), now recorded as `plantTint` and replayed by the test.
- New fixtures (111, appended after the 581 batch 38 ones, which are byte-identical): iron bars (101) in all 16 horizontal masks plus bars next to bars, panes, glass, stained glass, stairs and slabs; pumpkin and melon stems (104, 105) at age 7 next to their fruit in each direction, two fruits, the other stem's fruit, age 6 and age 3; tall grass (31 metas 0-2), dandelion, red flowers, double plants (lower and upper), lily pads, fire, and unhashed plants (dead bush, sapling, mushrooms, reeds) at (37,70,-22), (-5,3,129), (1000,64,-1000), (-33,200,17), (12345,12,-6789), (0,0,0) and a few more; a fern pot away from (8,8,8). Fixtures carry `pos`.
- Probe fix that the positions needed: `Chunk.getSavedLightValue` is called with chunk-local x/z for blocks that do not read neighbour brightness (pot box, bars' neighbour lights), so away from (8,8,8) the old single stand-in chunk returned garbage light (a flat 15/14). The probe now has one chunk object per chunk coordinate that maps local back to world cells (`LightFloatProbe.W.chunkAt` hook, `RenderTypes2Probe.C2`); the tile entity map is per chunk. The 581 older records did not change.
- Port bugs the new records found in iron bars (`ChunkMesher.pane`, render type 18, which had only been bytecode-read): the z-axis planes and strips were emitted with x and z swapped (the `pair` helper treated `[x,y,z]` lists as `[z,y,x]` for axis z), so any bar with a z arm was drawn rotated 90 degrees; and the top/bottom strips ask `isOpaqueCube`, which is false for fancy leaves (`doors-panes.js` `paneSideRendered` now uses the leaf rule; connection still uses `renderAsNormalBlock`, true for leaves, as the executed masks show).
- Held/inventory gate: `scene.js` imported `gateRenderBoxes` but never used it (dead import, removed). The native item path is not the world path: `RenderBlocks.renderBlockAsItem` has a separate render type 21 branch (three boxes: two posts `[7/16,.3,0,9/16,1,1/8]`, `[7/16,.3,7/8,9/16,1,1]` and one bar `[7/16,.5,0,9/16,15/16,1]`, bytecode-read), so `gateRenderPlan` does not apply. The boxes are saved as `GATE_ITEM_BOXES` in `src/render-shapes.js`; the inventory/held gate is still not drawn with them (block-textures `iconRaw` has no gate case, `first-person.js` has none either). `gateRenderBoxes` is marked superseded.
