# Ring pistons, hoppers and hopper carts track (batch 37, branch batch37-ringpistons)

## Summary
- **Native evidence.** `tools/verify-ring-pistons.mjs` (javap, bytecode-read, nothing executed) writes `public/research/ring-pistons-reference.json`: BlockPistonBase, BlockPistonExtension, BlockPistonMoving, TileEntityPiston, TileEntityHopper and EntityMinecartHopper make no World chunk-existence call; `World.updateEntities` runs a tile entity after `!isInvalid`, `hasWorldObj` and `blockExists(x, y, z)` (own chunk only). WorldServer's own block-event delivery was not read.
- **Pistons and redstone.** Tick for tick replays (`src/ring-pistons.test.js`: push, sticky retract, lever/wire/repeater/piston line; 120 ticks; changes, moving tiles, random stream and final cells) are identical between a ring-backed world and the all-resident world, both for scenes straddling the resident window edge and for scenes in ring columns. The real fault was at the rim: a piston whose 13-cell line reached an unheld chunk read it as air, so a neighbour update decided once (never retried), or a pushed block was written into a dropped column (a stone was lost). `LiveRedstone.eventActive` now keeps a block event queued until the column takes writes and the chunks within 14 blocks are held; `tileActive` runs a moving piston block when its column takes writes and the chunks within 2 blocks exist (small hook in `redstone.js updateTileEntities`). Waiting events stay in the saved event lists. Scheduled redstone ticks keep the eight-neighbour guard on purpose (wire updates read further).
- **Hoppers.** `Hoppers.tick` only ran in the resident ticking window. `main.js` now passes `hopperActive` (`hopper.js`, `ringBlockTickActive` with reach 1), so hopper blocks in ring columns move items and pick up ring item entities. Container stores are position-keyed, so they were already reachable.
- **Hopper carts.** They already read ring cells during the simulation tick. `hopperSuck` now waits while the cart's held column takes no writes (unhydrated), instead of reading stale blocks. `src/ring-hoppers.test.js` replays hopper blocks and hopper carts (chest above, chest below, dropped items) in ring chunks and the resident halo against the all-resident world.
- **Miss cache.** The `World.chunkAt` ring miss cache was already there (batch 26, "Round 8"); I changed nothing in `world.js`. Node timing, load average 9.6 to 10 (battery): 2 M ring `World.get` reads 29 ms with the cache, 71 ms with a plain map lookup per miss.
