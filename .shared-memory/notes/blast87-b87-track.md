# Batch 87 blast87: the player's feet in the blast list, a server player's TNT (fireballs, kill credit), skeleton TNT, ocelot look

## Summary
- **The player is filed by posY, the feet (executed).** `World.getEntitiesWithinAABBExcludingEntity` walks the slices `floor(posY / 16)`. The server's EntityPlayerMP has yOffset 0, so its posY is the feet (a sleeper's is minY + 0.2). The port filed him by the eye. Now `candidate-order.js` has `stampPlayerCell(p)`, which stamps the feet, and `posOf` uses the box minY / `posY` for the player too. `explosion-simulation.js` applyExplosion's player row and `server-mobs.js` explode's player rows use `serverPosY(...)`.
- **BlastOrderProbe case `feet` (executed, 200 scenes).** A Random(87) generator builds the scenes. In 167 of them the player's feet and eye straddle a slice border. There are 112 with player moves, some of which cross a border by the feet alone, and 93 with nested crystal blasts. The other entities are items, orbs, arrows, TNT, zombies, pigs and at most one crystal. `blast-order-reference.json` went from 1900 to 2100 records (+150 KB). The old records and class digests are byte-identical. `verify-blast-order.mjs` asserts 200 feet records.
- **Server fireball in a player's TNT blast (bytecode-read ze.a(ro, F)).** `server-mobs.js` explode passed `placer: byPlayer ? null : placer`, so a server player's TNT never turned a large fireball. It now passes the placer. `Fireballs.hitBall` with a server player record sets `owner = "player"` and `punchedBy = p`, as a punch does, so `fireballWatch` credits him. `lookOf` converts his port radians to rotationYaw = 180 - yaw°, rotationPitch = -pitch° and applies `lookVector`.
- **Server kill credit from a player's TNT (bytecode-read ro.a(agw), agw.c(), sv.a(ro,F), sv.a(ro)).** `mobRows` now gets `attacker: 'player'` with the placer's position and survival, or a mob placer, or null. Before, it got the TNT entity. The mobs take `mobs.damage(..., byPlayer, type, { name: "explosion", looting | shooter })`: recentlyHit 100, attackingPlayer, Looting from the placer's held item, and knockback and revenge from the placer. `explode` sets `achievements.attacker = placer` and `use(view)` around `runBlastRows`, so mobKills, `stat.killEntity.*` and the XP drop go to him. **Changed:** TNT with no placer (powered, dispensed, burnt) is now a plain "explosion" with no source entity, so the hazard path applies and there is no attackEntityFrom knockback. Before, it pushed from the TNT. The doExplosionA push is unchanged. Single player and server mobs keep the `explosion` flag in the source, so a mob's Blast Protection now counts (the old source name was "player" / "mob").
- **Skeleton's burning arrow on server TNT (bytecode-read aob.a(ahb,III,sa)).** `func_150114_a(..., zc.c instanceof sv ? zc.c : null)`. `server-dispense.js` tickLane `igniteTnt` now takes bow.js's `a.shooter` when no player owns the arrow (`ctx.tntPlacer ?? shooter object`), so the skeleton is the placer, the knockback source and the revenge target.
- **Ocelot tempt degrees (port-read, fixed).** `OcelotTempt.continueExecuting` multiplied `ew.playerLook()` by 180/π, but main.js `playerLook` already returns degrees (`playerEye`: 180 - yaw°, -pitch°). So a 0.09° turn scared the cat off, where native vk allows 5°. It now reads degrees. `enderman-wolf-replay.js` had fed `playerLook` with radians to match the bug. It now keeps `ew.look` in port radians (enderman stare) and gives `playerLook` the recorded degrees.
