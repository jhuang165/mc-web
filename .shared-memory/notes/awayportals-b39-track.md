# awayportals (batch 39)

## Summary
- Away-run mobs, items and orbs travel through portals (goal 1). `away-entities.js` runs `EntityPortals` for them after each run tick, like carts and boats; the departure record and transfer input come from the new shared `entityDeparture` in `entity-portal.js` (`dimension-live.js` `depart` uses it too, so live and away build the same record). Entities outside the 32-block rule and mobs with a rider or vehicle are skipped. `finishAway` delivers them through the same `deliver` (shared Teleporter, destination inbox). A delivered mob loses its id in `deliver` (new id on load), so there is no copy left in the Overworld and the Nether list holds it once.
- Arrival tick (goal 2). Each traveller carries the run tick it left at; `finishAway` computes total time = return time - run ticks + that tick (monotone, capped at the return) and passes it to `deliver` -> `shareTeleporter(root, to, peek, time)`. Cache entry times and the lazy 100-tick sweeps see the tick of the run. Not exact to the tick: the offset between the run's tick index and native total time (increment before entity updates) is unproven; documented in `public/research/loading-screens.md` "Batch 39 away portals".
- Executed probe (goal 3). `EntityPortalProbe.java` mode `mount`: the real minecart and boat touch the portal at tick 0, a rider is set at tick 1, and the vehicle still travels at tick 1. Pinned in `entity-portal.test.js` (vehicle records 8 -> 10, reference JSON regenerated, 101 records). Player dismount stays bytecode-read.
- `advanceTicks` test (goal 4). `main.js` `advanceTicks` now calls the exported `advanceWorldClock` (`dimension-live.js`); unit test covers total time, weather, day clock, `timeFrozen`, unloaded total time and non-positive input.
- Finding: non-player entities have maximum in-portal time 0, so mobs, items and orbs leave the tick after touching portal blocks; the away test checks departure ticks 1 to 3.

## Verification
- Focused: `away-entities.test.js` 9 pass, `entity-portal.test.js` 27 pass, `dimension-live.test.js` 22 pass, `dimension-away.test.js` + `away-world.test.js` + `module-names.test.js` 14 pass. Probe: `MC_RESEARCH=... node tools/verify-entity-portal.mjs` (load ~5) regenerated `entity-portal-reference.json`. The full suite and `npm run build` were left to the lead.
- Browser (muted headless Chrome, port 5394, load 5 to 6, `artifacts/b39-awayportals/probe-run.mjs`): on a fresh world, a lit portal built next to the player, a pig record, an item and an orb placed inside it, the real `runAway` on the live world's chunks (150 ticks), then the real `DimensionLive.finishAway` with that result through a stub worker. All three left at tick 1 with cooldown 300; `deliver` was called once each; the Nether inbox held the pig once (id dropped), one drop, one orb and 80 Teleporter writes; no pig record, drop or orb stayed in the Overworld lists; no page errors. The delivery time argument was 0 because the stand-in run was longer than the page's clock (clamped at 0): the time arithmetic is covered by the unit test only.
- Not achieved: a full player trip (`away.mjs`, Overworld to Nether and back with the entities standing in the portal during the run). The Nether entry stayed on "Downloading terrain" for 240 s in most runs that had a pig or recorded portal edits (also with the baseline `src` files restored, so it is not caused by this branch; cause not found). The one run that entered the Nether had an unrecorded portal that the run's chunks did not hold, so nothing travelled there.

## Follow-ups (proposed gap lines)
- Full-trip browser check of away portal travel is missing: the Nether entry intermittently hangs on "Downloading terrain" (240 s) in scripted trips with extra saved entities or portal edits, also on the batch 38 code. Needs its own investigation.
- Away arrival time: the run tick to native total-time offset (one tick) is not proven; matters only within a tick of a multiple of 100.
- Away-run entities that are parked (outside the 32-block rule) still do not reach portals; a ridden cart or mob in the run is not simulated.
- The dismount of a player on a cart that leaves in the same tick is bytecode-read only; the probe uses a stand-in rider.
