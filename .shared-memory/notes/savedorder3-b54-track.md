# savedorder3 (batch 54)

## Summary
- Section check per entity: `EntityWorld.tickMobs` now runs `trackSections(this, [entity])` right after each entity's own update and rider seat (at the start of the next turn, and once after the loop), instead of one pass over the list at the end. An entity another entity pushed across a section after its own turn is refiled at its next turn, as natively. The start-of-pass call that records where each entity is filed is unchanged. Edit in `src/entities.js` is a 3-line local helper (`sections`) at the loop head.
- Player's mount: natively the chunk writer skips a ridden mount and the player's NBT nests it under `Riding`; ServerConfigurationManager.initializeConnectionToPlayer reads it back with `EntityList.createEntityFromNBT`, `forceSpawn`, `World.spawnEntityInWorld` and `mountEntity`, after the chunks. In the port `carriesPlayer` (saved-order.js; carts/boats with `rider.player`, mobs seated by horse-live) takes such a mount out of the chunk walk and stamps it last. The browser JSON keeps the record in its own list (cart `rider: true`, mob `playerRides`) so existing saves load unchanged: only the order follows the native shape; the away run does not treat the carrier specially (it still ticks it, as before).
- y above 256: `EntityWorld.restore` rejected `e.y >= world.height`, so the away run (and any load) dropped a mob saved at y >= 256. Natively AnvilChunkLoader loads it (Chunk.addEntity clamps to section 15); the upper bound is removed (void, y < -64, unchanged).
- removedHealth audit of `health = 0` removals: despawn (`ai.despawn`, used by despawnEntity, silverfish and giant setDead; it only set `despawnedHealth`) and the dragon's death end (`dragonGone`) now set `removedHealth` too. Already correct: cure, shear, creeper blast, peaceful removal. Ender crystal: natively `health = 0` before setDead (attackEntityFrom), so it stays 0. Villager killed by a zombie / `removedNow`: health is left untouched (never zeroed). Slime/mob death animations end with health <= 0 natively. Other `health = 0` sites are the away run's stand-in survival and object-tracker placeholders (not mobs). Readers of removedHealth are still only the replay harnesses.
- Correction: the b52/b53 probes called `apx.d()`, which is Chunk.onChunkUnload (appends the same per-section lists to `ahb.f`, the unloaded list), not onChunkLoad (`apx.c()`, `ahb.e` = loadedEntityList). Both walk sections 0..15 over the same lists, so the references hold; the new scenarios use `apx.c()`.
