# Batch 78 spexec78: executed probes for jukebox, thrown entities, fireballs, milking and mooshroom shearing

## Summary
- New executed probes `tools/probes/SpExec78Probe.java` (thrown, pearl, fireball), `SpExec78Milk.java`, `SpExec78Jukebox.java`, run by `tools/verify-spexec78.mjs` into `public/research/spexec78-reference.json` (208 records, 6 kinds) on the unchanged 1.7.10 jar. Every case runs on a server world and a client world (the SP client also runs `interactWith`, `onImpact` and `playAuxSFX`).
- Replay test `src/spexec78-b78.test.js` (14 tests).
- Fix 1, `src/projectiles.js`: `GaussianRandom` overrode `nextGaussian` with `Math.log`; native `Random` uses `StrictMath.log` (fdlibm), which differs by an ulp for about 0.6 % of draws. One of the 32 ender pearl portal particles of the record was off in its last digit. The override is gone; the class inherits `java-random.js` (`strictLog`). This also corrects every other Entity.rand gaussian that goes through this class (pearl particles).
- Fix 2, `src/main.js` (2 lines): no "Now playing" HUD line on aux 1005. Native `RenderGlobal.playRecord(String)` looks the string up with `ItemRecord.getRecord("records.<name>")`, but the map is keyed by the bare name, so the lookup misses and `GuiIngame.setRecordPlayingMessage` is never called. The disc sound still starts. `createRecordHud` stays (mount.onboard uses it).
- Fix 3, `src/entities.js` (1 condition): fire resistance now refuses fireball damage whichever source type it has (`source.fireball`). Native `EntityLivingBase.attackEntityFrom` returns false for `isFireDamage()` with fireResistance, and `causeFireballDamage` is fire damage in both forms (type fireball with a shooter, onFire without). The port only checked the names onFire, inFire and lava.
- No old test encoded these gaps; none was changed.
