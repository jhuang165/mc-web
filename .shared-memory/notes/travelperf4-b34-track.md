# travelperf4 (batch 34)

## Summary
Goal: finish the portal-trip prewarm (saved portals, Nether second fetch), cut ring-light search cost, check creative travel. No game rule changed; no Java probes (nothing native re-derived, all results are the output of the same generators).

- Saved portals (goal 1). `DimensionLive.warmExit` now reads the destination's saved portal columns once per trip (`savedPortals`: the destination's edits, the portal arrivals of mobs, and imported stored columns, the same sources `peekFor` and the Teleporter use) and passes them to `ExitPrewarm.start(root, to, tt, portals)`. `savedPortalFor` (exit-prewarm.js) picks what `Teleporter.placeInExistingPortal` would pick: the nearest column inside the 128-block box, first in x-then-z order on a tie (horizontal distance only; the real search also weighs height, which the column list does not carry; a wrong pick only wastes the prewarm). The windows (`need`, then the 18-block spread) are asked for round that portal instead of round the target. Nothing is asked for until the list is known (an IndexedDB read, milliseconds); the first tick that asks starts the request when the list arrives. `peekFor` is NOT used: for the Overworld it builds a `World`, whose constructor takes the parked resident cell (`presolvedCells`) the return trip waits for. A first version that did use it made the return trip wait 1.1 s longer at `trip:terrain`; found and fixed (the mark timeline is in the verification).
- Nether second fetch (goal 2). The Nether shell now takes `specMax` 40 (it was `null`, which left no spare lane, so only the target's 8 x 8 columns were built). The windows round every spot within 18 blocks of the target union to at most 10 x 10 columns, so at most 36 more columns. Memory budget: a Nether column is about 33 KB of blocks and metadata, so at most about 1.2 MB held, freed at adoption or after 30 s. Unit test: the window of an exit 8 blocks east of the target is fully held, and held columns equal `DimensionWorld.generateTerrainChunk`.
- Ring-light per-frame cost (goal 3). Cause found with a node microbenchmark (`artifacts/b34-travelperf4/bench-search.mjs`, fixed inputs, min of 7 alternating runs, seed `walkperf31`): a surface cell (sky 15 at once) still ran the whole 29 x 29 x 29 block-light spread whenever any of its 3 x 3 held chunks held any emitter, and nearly every chunk has lava far underneath. `RingLight.info` now also keeps the lowest and highest emitting y of a held column; `search` only asks for block light when an emitting chunk's range overlaps `qy +- 14` (an emitter further away gives `emission - distance <= 0`, which can never beat the start value, so the answer is unchanged). Resident chunks still answer "may have both" (not scanned), so cells whose 3 x 3 neighbourhood touches the resident window are unchanged.
- Creative travel (goal 4). Not changed. `maxInPortalTime` is 0 for a creative player, and `DimensionLive.tick` calls `setInPortal` and `PortalState.tick` in the same tick, so the trip starts on the first tick inside the portal block: there is no countdown and nothing earlier than that tick to hook (a check on entering the block is the same instant). Starting before that would mean guessing from the player approaching a portal (distance or look direction), which builds a world's worth of cells for walks that do not enter. Left as is; the loading screen covers the wait.

## Follow-ups (proposed gap lines)
- The saved-portal pick is horizontal-nearest; the Teleporter also weighs height. Two stacked or near-equal portals can make the prewarm build the wrong window (waste only).
- Resident chunks are not scanned by the ring-light `info`; a cell whose 3 x 3 touches the resident window still runs the full block-light search when any emitter might be near (about 50 us). Tracking emitter y-ranges of resident chunks would need an edit hook.
- Browser frame-time effect of the ring-light change is unmeasured (only the node microbenchmark).
- Creative travel (instant) has no countdown; nothing safe starts earlier than the first tick in the portal block.
- A saved portal exit whose window crosses into more cells than `specMax` 5 allows (Overworld) is still partly built after the countdown.
