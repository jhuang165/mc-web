# playerthrows (batch 46)

## Summary
Server-side player-thrown entities (live world only), with executed evidence from `tools/probes/EntityListProbe.java` (now 63 scenarios plus 25 launch records; the first 49 scenarios are byte-identical).

- **Launch (gap 1), executed.** `EntityThrowable(World, EntityLivingBase)` (bytecode-read: position from the thrower's eye, 0.16 sideways, 0.1 down, motion 0.4 along the view, then `setThrowableHeading(motion, func_70182_d(), 1.0F)`; `func_70183_g()` only tilts the vertical motion) was run unchanged for EntitySnowball, EntityEgg, EntityEnderPearl, EntityPotion and EntityExpBottle on a player shell, 5 views each (`launches` in `public/research/entity-list-reference.json`). Entity.rand is created unseeded, so each record holds the Random state before the aim, recovered by stepping the LCG back until three `nextGaussian` draws reproduce the state the constructor left. Result: every player throw draws exactly the three gaussians of one aim (inaccuracy 1.0), in the order x, y, z; the witch's extra pre-aim of batch 45 is its own path (inaccuracy 0 first, then its own aim) and the player path was not missing draws. Snowball, egg and pearl (`launch`) matched. **Bug found:** the potion and experience bottle launch (`WitchPotions.throwFromPlayer`) used `Math.sin/cos` instead of MathHelper's sine table, so every thrown bottle differed at about 1e-5 (start, motion, rotation). It now calls `launch(rand, feet, yaw, pitch, velocity, -20)`.
- **Carts and boats as targets (gap 2), executed.** The player's snowballs, eggs and pearls (`main.js` `projectileTargets`) now take the carts and boats (`vehicleTargets`, `entity-simulation.js`). Native: the ball's ray takes any `canBeCollidedWith` entity; `onImpact` calls `attackEntityFrom(DamageSource.causeThrownDamage(ball, thrower), 0)`. A cart or boat wobbles (rolling amplitude 10 and direction flip, damage + 0; boat timeSinceHit 10), the ball dies. The indirect source's entity is the thrower, so a Creative player's snowball, egg or pearl breaks the cart or boat outright (`flag` in `attackEntityFrom`, bytecode-read; records `pthrow-snowball-cart-creative`, `-boat-creative`, `pthrow-pearl-boat-creative`), with no drop. Splash potions (and exp bottles, via the potion walker) already targeted vehicles and leave them untouched (`pthrow-potion-cart`). New `thrownAtVehicleOrHanging` (entity-simulation.js) is shared by main.js and the replay; `minecarts.attack/boats.attack` get `creative` for the player's throw.
- **Egg and pearl on a painting (gap 3), executed.** `pthrow-egg-painting`, `pthrow-pearl-painting`, `pthrow-snowball-painting` (a non-Creative thrower: the painting breaks and its item joins the entity list on the hit tick) and the `-creative` forms (no drop) replay exactly. The probe pearl thrower is an EntityPlayerSP shell, so the `instanceof EntityPlayerMP` teleport branch is not taken (the pearl teleport stays covered by `pearl-player` tests).
- **Pearl moves once after impact.** Native `EntityThrowable.onUpdate` goes on after `onImpact` and moves the dead pearl once more; the port returned early for pearls. Removed (the `ender-pearl-live` and `pearl-player` tests now compare the teleport with the position at impact).
- **Replay.** `entity-list-replay.js` builds a real `Projectiles` for the walk and a `pthrow` kind (ball at a given point and motion, type 0 snowball, 1 egg, 2 pearl, 3 potion; b = Creative thrower), with the same `projectileTargets/projectileHit/projectilePearlImpact` code path as main.js. Cart rows (`pthrow-*` only) end with damage, rolling amplitude and rolling direction, boat rows with damage. Negative control `without = "throwTargets"` (old targets: hanging only) diverges on all vehicle records.
